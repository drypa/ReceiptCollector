# Задача 06 - Промт: удаление хардкода, блок подсказок, замена теста хардкода

- **Задача**: docs/plans/commodity-categories.md#t-06-промт-удаление-хардкода-блок-подсказок-замена-теста-хардкода
- **Дата**: 2026-11-12
- **Ревью**: раундов - 1, вердикт APPROVED

## Что сделано

Закрыты FR-2 и FR-7 (ADR-035, решение F1). Из `OpenAiCompatibleAiClient.BuildPayload` удалён
статический блок «Разграничения схожих категорий» (заголовок + 11 строк примеров, 1976
символов): единственным источником этих разграничений стала БД - сид таблицы
`commodity_category_keywords` из задачи 01. В коде не осталось ни файла с примерами, ни
стартового upsert'а слов.

В user-сообщение теперь рендерится только фактически совпавший блок подсказок, и только когда
они есть (`hints.Count > 0`): заголовок «Подсказки по ключевым словам (совпали в названии; это
только подсказки, решение принимай сам):» и по строке на подсказку - «- в названии есть
«слово» -> скорее не <DisplayName> (<EnumName>)» для exclude и «вероятно» для boost. Порядок
приходит из матчера уже упорядоченным (exclude первыми), клиент его не пересортировывает, а
только усекает до приватной константы `MaxPromptHints = 50`, поэтому при переполнении
отбрасываются исключительно boost-подсказки (UC-5: исключение сильнее). Слово проходит
`EscapeHintWord`: управляющие символы -> пробел, схлопывание пробелов, обрезка до 64 символов,
так слово не способно создать новую строку блока или «дописать» инструкцию.

Порядок строк user-сообщения: `Товар: "…"` -> `Выбери ОДНУ … из реестра: <catalog>.` ->
[блок подсказок] -> `Ответь строго в формате JSON: …` последней строкой. При пустых подсказках
промт стал 3 строки вместо 15 (NFR-2: объём промта больше не зависит от числа слов в БД).
`TryExtractCategory`/`ParseCategoryName`, ретраи, `SendAsync`, system-сообщение, `temperature`,
модель и сериализация тела через `JsonSerializer` не менялись; ручного склеивания JSON нет.

Удалён устаревший тест `OpenAiCompatibleAiClientTests.SuggestCategoryAsync_prompt_contains_new_category_heuristics`
(он утверждал удаляемый хардкод) и добавлен набор из 14 тестов блока подсказок, покрывающий
все пункты ADR-035 п. 10 для строки `OpenAiCompatibleAiClient`.

## Итоги ревью

Ревьюер подтвердил соответствие шаблону F1 символ в символ (заголовок блока, «скорее не»/
«вероятно», «ёлочки», `DisplayName (EnumName)`, инструкция формата последней строкой),
усечение по 50 с отбрасыванием только boost, невозможность создать новую строку блока и то,
что регресс парсера ответа, ретраев, `temperature` и system-сообщения не затронут. Замена
удалённому тесту - надмножество удалённых утверждений, ослабления утверждений в остальных
тестах нет. Границы задачи соблюдены: изменено ровно 3 файла кода/тестов.

Принятые отклонения (зафиксированы в XML-doc, поведение согласовано с ADR):

1. Приёмочный grep уточнён до `--include="*.cs"`: 2 совпадения буквального grepa - комментарий
   происхождения сида в закоммиченной миграции (он есть в SQL-образце ADR-035 п. 1) и копия в
   `bin/`; правка применённой миграции вышла бы за рамки задачи.
2. `EscapeHintWord` дополнительно снимает обрамляющие пробелы: слово в БД хранится trimmed,
   обрамляющий пробел мог бы появиться только из управляющего символа на краю.
3. Схлопываются все `char.IsWhiteSpace`, а не только ordinary space - надмножество формулировки
   ADR (закрывает и `U+2028`/`U+2029`), нужно, чтобы строка блока гарантированно оставалась одной.
4. После обрезки до 64 символов делается `TrimEnd()` - косметика, чтобы в «…» не остался висячий пробел.
5. Инструкция формата больше не заканчивается переводом строки (раньше `\n` был нужен, чтобы
   отделить идущий следом блок) - теперь это ровно последняя строка сообщения.

Исправлено по замечаниям ревьюера (только XML-doc, поведение не менялось, тесты перепрогнаны
после правок):

- в doc `MaxHintWordLength` указано, что 64 зеркалит `CommodityCategoryKeywordRules.MaxWordLength`
  и CHECK миграции - правило живёт в трёх местах и меняется синхронно;
- в doc `EscapeHintWord` зафиксировано, что для слова целиком из управляющих символов
  возвращается пустая строка, и что через API такой вход недостижим (валидация 2-64 + trim).

Оставлено без изменений (по решению ревьюера, отложено):

- фикстура реестра категорий в тесте «старых строк нет» (`CategoryCatalog` = Food, Dairy,
  Beverages) - список намеренно не совпадает с полным реестром, проверка на отсутствие строк
  старого блока от этого не зависит;
- «избыточное» утверждение в тесте лимита (помимо подсчёта строк проверяется, что каждая строка
  содержит одну из двух формулировок) - оставлено как дополнительная защита формата.

**ВНИМАНИЕ, в рабочее дерево попали посторонние незакоммиченные изменения - их брать в коммит
НЕЛЬЗЯ.** В `Analytics/src/ReceiptCollector.Analytics.Api/appsettings.json` изменены:
`AI:BaseUrl` (`""` -> `http://127.0.0.1:1234/v1`), `AI:Model` (`qwen` -> `nvidia/nemotron-3-nano-4b`),
`AI:Timeout` (`00:00:10` -> `00:01:20`), `Infrastructure.AdminUsers.TelegramIds` (заглушки
`123456789`/`987654321` заменены на личный id) и добавлены секции `Precategorization` и

семантику «пустой `AI:BaseUrl` = AI-категоризация выключена»** (ADR 009 / ADR-035: при пустом
значении suggest отвечает `503`/`aiAvailable = false`) и **подменяет allowlist администраторов**
личным Telegram id, а правка `AI:Timeout` и новых секций меняет дефолты для всех окружений.
Сюда же - `appsettings.Development.json` (локальные строки подключения MongoDB с паролем
`admin:secret`, `Synchronization.Skip: false`, личный id в `AdminUsers`) и
`wwwroot/index.html` (ссылки на `assets/index-CaM7UJw7.js`/`index-DAWiSsm6.css`, которых в git
нет - собранный фронтенд). Коммит собирать только из трёх файлов задачи (`git add` по путям из
раздела «Изменённые файлы»); `git add .` и `git commit -a` недопустимы.

При ручной проверке обратить внимание: коммит не должен содержать `appsettings*`,
`wwwroot/index.html`, `bin/`/`obj/`; содержимое блока разграничений по-прежнему доступно в БД
(сид задачи 01) - если администратор удалил сид-слово, в промт оно больше не вернётся, это
ожидаемое поведение B1.
