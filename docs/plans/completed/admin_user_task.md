# Задача: Установка признака IsAdmin для пользователей по списку Telegram ID

## Описание задачи:
Необходимо реализовать логику установки признака `IsAdmin` в сущности `UserEntity` при каждом запуске сервиса Analytics. Сервис должен читать список Telegram ID администраторов из конфигурационных параметров и для соответствующих пользователей устанавливает `IsAdmin = true`.

## Требования:
1. При старте сервиса Analytics читается переменная окружения или конфигурация с перечнем Telegram ID администраторов
2. Для всех найденных пользователей в БД Postgres, чьи `TelegramId` находятся в списке, устанавливается `IsAdmin = true`
3. Если пользователя нет в БД (он не найден), запись пропускается 
4. Если пользователь найден, но его Telegram ID не указан в списке - признак IsAdmin не должен сбрасываться
5. Вся логика выполняется при каждом запуске сервиса

## Конфигурация:
Добавить секцию `AdminUsers` в файл `appsettings.json`:

```json
{
  "Infrastructure": {
    "AdminUsers": [
      123456789,
      987654321
    ]
  }
}
```

## Решение:
1. Создать класс для конфигурации `AdminUserOptions` в `ReceiptCollector.Analytics.Infrastructure.Configuration.Options`
2. Добавить сервис для работы с пользователем, который будет:
   - Загружать список Telegram ID из конфигурации
   - Читать всех пользователей из Postgres БД
   - Устанавливать `IsAdmin = true` только для пользователей с указанными Telegram ID
   - Обновлять данные в БД для этих пользователей

## Требуемая реализация:
- Использование Entity Framework для работы с PostgreSQL
- Проверка существующих пользователей в БД по Telegram ID из конфига
- Только обновление нужных записей, без изменения остальных данных
- Обработка ошибок при работе с БД

## Важные замечания:
1. Сервис должен работать при каждом запуске приложения 
2. Не нужно удалять или модифицировать пользователей, которых нет в списке
3. Реализация должна быть idempotent - повторный запуск не должен изменять данные для уже обработанных пользователей
4. Добавьте логирование процесса обновления данных

## Контрольные точки:
1. Секция AdminUsers добавлена в конфигурационный файл
2. Класс AdminUserOptions создан и зарегистрирован в DI контейнере  
3. Сервис обновления IsAdmin реализован корректно
4. Все пользователи с указанными Telegram ID получили IsAdmin = true
5. Никто не был уволен из админов по ошибке
