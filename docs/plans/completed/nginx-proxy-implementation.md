# Реализация Nginx прокси для аналитических сервисов в разработке

## Описание задачи
Добавить Nginx прокси сервис в docker-compose.develop.yml, который будет выступать в роли обратного прокси для аналитического API и фронтенд-сервиса, позволяя использовать единый порт для доступа к обоим компонентам.

## Задачи

### 1. Обновление Docker Compose файла
**Описание:** Добавить сервис Nginx в docker-compose.develop.yml с необходимыми настройками конфигурации и маппингом портов.
- Добавить сервис nginx с образом nginx:alpine
- Настроить контейнер с именем receipt-nginx 
- Открыть порт 8080 для внешнего доступа (внутри контейнера будет порт 80)
- Подключить volume с конфигурационным файлом nginx.conf
- Добавить сетевой интерфейс к сети collector-net

**Зависимости:** 
- Наличие docker-compose.develop.yml в проекте (проверено)

**Приоритет:** P0
**Оценка времени:** 1 день

### 2. Создание/обновление конфигурационного файла Nginx
**Описание:** Подготовить или обновить файл nginx.conf для проксирования запросов к аналитическим компонентам:
- Настройка upstream для аналитического API на порту 8085 
- Настройка upstream для фронтенда на порту 3000
- Конфигурация сервера с прослушиванием порта 80
- Обработка запросов к /api/ для проксирования в API сервис
- Обработка остальных запросов для проксирования в фронтенд

**Зависимости:** 
- Наличие файла nginx.conf (проверено)
- Сеть collector-net должна существовать (проверено)

**Приоритет:** P1
**Оценка времени:** 2 часа

### 3. Проверка настройки сети Docker
**Описание:** Убедиться, что сетевая конфигурация позволяет контейнерам корректно взаимодействовать:
- Подтвердить наличие сети collector-net в docker-compose.develop.yml (проверено)
- Убедиться, что все сервисы могут корректно подключаться к сети

**Зависимости:** 
- Сетевые настройки Docker Compose
- Наличие необходимых сервисов для взаимодействия 

**Приоритет:** P2
**Оценка времени:** 1 день

### 4. Проверка конфигурации host.docker.internal
**Описание:** Убедиться, что в среде разработки корректно настроен доступ к хосту из контейнеров:
- Протестировать резолвинг имени host.docker.internal 
- Подтвердить, что порт 8085 доступен с контейнера
- Подтвердить, что порт 3000 доступен с контейнера

**Зависимости:** 
- Доступ к хостовой системе из Docker контейнеров
- Запущенные аналитические сервисы на портах 8085 и 3000

**Приоритет:** P1
**Оценка времени:** 2 дня

### 5. Тестирование функциональности прокси
**Описание:** Проверить, что Nginx корректно маршрутизирует запросы:
- Проверка доступа к API через /api/ endpoint (порт 8080)
- Проверка доступа к фронтенду по стандартному URL (порт 8080)
- Убедиться, что все HTTP заголовки передаются корректно

**Зависимости:** 
- Запущенные сервисы
- Nginx контейнер запущен и работает

**Приоритет:** P0
**Оценка времени:** 2 дня

## План выполнения:
1. Обновить docker-compose.develop.yml (Задача 1) 
2. Подтвердить/обновить nginx.conf (Задача 2)
3. Проверить сетевые настройки (Задача 3)
4. Проверить конфигурацию host.docker.internal (Задача 4)
5. Тестирование функциональности (Задача 5)

## Критический путь:
1. Задачи 1 и 2 - первоначальная настройка
2. Задача 3 - проверка сетевой конфигурации 
3. Задача 4 - подтверждение доступности хоста из контейнера
4. Задача 5 - тестирование функциональности

## Критерии приёмки:
- Nginx контейнер запускается без ошибок
- Все сервисы корректно разворачиваются в Docker Compose среде
- Веб-запросы к localhost:8080 направляются правильно (API или фронтенд)
- HTTP заголовки передаются корректно в прокси
