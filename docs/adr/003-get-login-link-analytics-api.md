# 3. Перевод GetLoginLinkCommand на вызов Analytics API

## Статус
Предложено

## Контекст
Текущая архитектура системы:
- Backend на Go с gRPC интерфейсом
- Telegram бот на Go
- Analytics сервис на .NET 8

Текущая реализация в боте:
- `bot/commands/login.go:14-21` - команда GetLoginLinkCommand
- Вызывает `grpcClient.GetLoginLink(ctx, telegramId)` для получения логин-ссылки
- gRPC метод реализован в `backend/users/processor.go:35`

Проблема: дублирование функциональности - ссылка генерируется через Backend (gRPC), но в Analytics уже есть endpoint `RequestAuthLink` с аналогичной функциональностью.

## Рассмотренные варианты

### Вариант 1: Оставить gRPC вызов к Backend
Преимущества:
- Не требует изменений в коде бота
- Архитектура уже работает

Недостатки:
- Дублирование логики генерации ссылок
- Дополнительная зависимость от Backend gRPC
- Сложнее поддерживать согласованность между сервисами

### Вариант 2: Добавить HTTP endpoint в Backend
Преимущества:
- Единообразный подход к API в рамках Backend
- Bot использует HTTP вместо gRPC

Недостатки:
- Добавление нового endpoint в Backend
- Дублирование функциональности с Analytics

### Вариант 3: Использовать Analytics API endpoint
Преимущества:
- Устранение дублирования функциональности
- Унификация API - бот использует HTTP для всех внешних сервисов
- Analytics endpoint уже реализован и покрыт тестами

Недостатки:
- Требуется добавить HTTP клиент в боте для Analytics
- Дополнительная конфигурация (URL Analytics API)
- Увеличение связности между ботом и Analytics

## Решение
Перевести GetLoginLinkCommand на использование Analytics API endpoint `GET /api/users/auth-link-request?telegramId={id}`.

Реализация:
1. Добавить HTTP клиент в bot для вызова Analytics API
2. Обновить GetLoginLinkCommand для использования HTTP вместо gRPC
3. Добавить конфигурацию ANALYTICS_URL в .env

## Плюсы решения
- Устранение дублирования логики генерации ссылок
- Упрощение архитектуры - бот получает данные из одного места
- Использование готового, протестированного endpoint
- Унификация - бот работает с HTTP API вместо gRPC

## Минусы решения
- Дополнительная зависимость бота от Analytics сервиса
- Необходимость добавления конфигурации для URL Analytics
- При недоступности Analytics бот не сможет выдать ссылку

## План реализации
1. Добавить ANALYTICS_URL в конфигурацию бота
2. Создать HTTP клиент для Analytics в bot
3. Обновить GetLoginLinkCommand для использования нового HTTP клиента
4. Обновить документацию и .env.example
5. Убедиться что endpoint работает корректно - проверить тесты
