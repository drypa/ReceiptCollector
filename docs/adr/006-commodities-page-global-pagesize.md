# ADR 006: Глобальное состояние pageSize через React Context

## Статус
Принято

## Контекст
В рамках задачи «Раздел «Товары» (Commodities)» требуется, чтобы размер страницы (pageSize) сохранялся при переключении между разделами «Чеки» и «Товары» в рамках одной пользовательской сессии.

Текущая реализация: `pageSize` хранится в локальном состоянии `ReceiptsPage` (`useState<number>(DEFAULT_PAGE_SIZE)`). При переключении на другой маршрут это состояние теряется.

Рассматривались варианты:
1. **React Context** — Provider на уровне приложения
2. **URL query-параметр** — `/receipts?pageSize=20` и `/commodities?pageSize=20`
3. **localStorage** — сохранять в браузере
4. **Глобальный модуль (singleton)** — простой JS-модуль с переменной

## Решение
Выбран **вариант 1: React Context**.

Создаётся `PageSizeContext` с провайдером на уровне всего приложения:

```tsx
<BrowserRouter>
  <PageSizeProvider>
    <Routes>...</Routes>
  </PageSizeProvider>
</BrowserRouter>
```

Хук `usePageSize()` используется в `ReceiptsPage` и `CommoditiesPage`:

```tsx
const { pageSize, setPageSize, pageSizeOptions } = usePageSize();
```

### Состав Context
- `pageSize: number` — текущий размер страницы
- `setPageSize: (size: number) => void` — сеттер
- `pageSizeOptions: readonly number[]` — варианты [5, 10, 20, 50, 100]

## Обоснование
1. **Единый источник истины** — оба компонента получают одно и то же значение.
2. **Простота** — нет внешних зависимостей, только встроенный React API.
3. **Жизненный цикл** — состояние живёт пока жива страница (SPA сессия). При перезагрузке — сброс к DEFAULT_PAGE_SIZE (ожидаемое поведение).
4. **Изоляция** — не затрагивает URL (не раздувает историю браузера).
5. **Тестируемость** — можно обернуть компонент в тестовый PageSizeProvider.

## Отклонённые варианты

### URL query-параметр
- Плюсы: сохраняется в закладки.
- Минусы: раздувает URL, требует синхронизации между обновлениями стейта и URL, неоднозначность при переключении между разделами.

### localStorage
- Плюсы: сохраняется между сессиями.
- Минусы: избыточно для UI-настройки, требует очистки при выходе, усложняет тесты.

### Глобальный модуль (singleton)
- Плюсы: максимально просто.
- Минусы: не участвует в реактивном обновлении React; изменение не вызывает перерендер компонентов без ручной подписки; сложно тестировать (shared mutable state).

## Последствия
- `ReceiptsPage` теряет локальное состояние pageSize — переходит на контекст.
- Все страницы с пагинацией используют один источник pageSize.
- При желании сохранять pageSize между сессиями (перезагрузка) можно добавить localStorage persistence в PageSizeProvider, но это выходит за рамки текущей задачи.
