# 22. Детализация продуктовых категорий: Сухофрукты, Соусы, Приправы, Колбасные изделия

## Статус

Проект (предложено к рассмотрению; задача: `docs/tasks/commodity-categories-food-details.md`, критерий приёмки «реализован словарь/маппинг "категория → группа"»).

## Контекст

Справочник `CommodityCategory` детализирован по ADR 010 (43 значения): продукты разбиты на 13 подкатегорий с кодами 18–30, транспорт — 31–37, прочие пробелы — 38–41, `Other = 255`. Заказчик выявил пробелы внутри продуктовой группы:

- **сухофрукты** (изюм, курага, чернослив, финики) — сейчас «Бакалея»/«Фрукты»;
- **соусы** (кетчуп, майонез, соевый соус) — сейчас «Бакалея»;
- **приправы/специи** — сейчас «Бакалея»;
- **колбасы/сосиски/сардельки** — сейчас «Мясо».

Реальные покупки не ложатся в существующие категории, из-за чего размывается аналитика расходов на питание.

### Ключевая техническая проблема

`CommodityCategoryHelper.GetGroup()` определяет группу `switch`-ом по **диапазонам кодов**:

```csharp
>= CommodityCategory.Beverages and <= CommodityCategory.FastFood => "Продукты",  // 18–30
```

Свободные коды начинаются с 42, т.е. новые продуктовые категории (коды > 41) **не попадут** в группу «Продукты» без рефакторинга. Привязка группировки к числовым значениям enum — хрупкое решение: она не само-документируется и ломается при каждом новом расширении справочника. Заказчик явно потребовал заменить диапазоны на словарь/маппинг «категория → группа».

### Текущее состояние (AS-IS)

- `CommodityCategory` — enum в `Domain/Modules/Commodities/CommodityCategory.cs`; `CommodityCategoryHelper` содержит `DisplayNames` (43 записи), `GetDisplayName()`, `GetAll()`, `GetGroup()` (диапазонный switch).
- Справочник для UI и для промта ИИ генерируется из `CommodityCategoryHelper.GetAll()`:
  - `GET /api/commodities/categories` (`CommodityEndpoints.ListCategories`, `CategoryDto { Id, Key, Name, Group }`) — group берётся из `GetGroup()`;
  - `CategoryNames` в `CommodityCategorizationService` — имена enum без `Undefined`, передаются в `OpenAiCompatibleAiClient.BuildPayload` (реестр в промте).
- Категория товара хранится denormalized: `commodities.category_id (int?)` + `commodities.category_name (varchar(128))` (ADR 005).
- Существующая реализация промта (`BuildPayload`) НЕ содержит эвристик/few-shot (описанные в ADR 009 эвристики кофе/чая и few-shot в коде не реализованы — отдельный пробел, вне этой задачи).

### Бизнес-требования (из задачи)

1. 4 новые категории в группе «Продукты»: **Сухофрукты, Соусы, Приправы, Колбасные изделия** (одна категория для колбас/сосисок/сарделек).
2. Новые категории доступны при ручной классификации на UI и учитываются автоклассификацией ИИ.
3. Существующие классификации и коды не трогаем — только добавление enum-значений.
4. Реализовать словарь/маппинг «категория → группа» вместо switch по диапазонам кодов в `GetGroup`.

## Рассмотренные варианты

### A. Нумерация новых значений

- **A1 (выбрано):** новые коды **42–45** последовательно, только добавление:
  `DriedFruits = 42`, `Sauces = 43`, `Spices = 44`, `Sausages = 45`. Диапазон свободен (заняты 0–17, 18–41 и 255), коллизий нет, `Other = 255` сохраняется. Значения размещаются после `Entertainment = 41` отдельным блоком с комментарием «Продукты (детализация, расширение) — коды 42–45».
- A2: переиспользовать «дыры» в 0–17 — отклонено: обратная совместимость данных и читаемость кодов важнее; правило «только добавление» зафиксировано ещё в ADR 010.

**Имена enum-членов** (уникальность обязательна для формата ИИ `{"category": "<имя>"}` и `Enum.TryParse`):

| Код | Enum | Отображаемое имя | Примеры для UI/промта |
|-----|------|------------------|-----------------------|
| 42 | `DriedFruits` | Сухофрукты | изюм, курага, чернослив, финики, сушёные ягоды |
| 43 | `Sauces` | Соусы | кетчуп, майонез, соевый соус, горчица, томатная паста |
| 44 | `Spices` | Приправы | перец, соль приправная, специи, лавровый лист, орегано |
| 45 | `Sausages` | Колбасные изделия | колбаса, сосиски, сардельки, ветчина |

Все имена уникальны, отображаемые имена ≤ 128 символов (лимит `category_name`), БД-схема не меняется.

### B. Группировка «категория → группа»

- **B1 (выбрано):** явный `Dictionary<CommodityCategory, string>` (категория → группа) + имена групп как константы; `GetGroup(category)` → `CategoryGroups.GetValueOrDefault(category, "")`. Точное соответствие пожеланию заказчика; нулевая зависимость от значений кодов; отсутствие категории в словаре = «без группы» (legacy 0–17 и `Other = 255` — как сейчас).
- B2: маппинг «группа → список категорий» с инверсией в словарь при инициализации — меньше повторений строки-группы, но менее прозрачно и сложнее (KISS против). Отклонено: заказчик просил «категория → группа», а 28 записей словаря читаются однозначно.
- B3: полный перебор через `switch` на enum-значения (без диапазонов) — тот же словарь, но менее data-driven; словарь предпочтительнее (легко мигрировать на конфиг/БД при росте числа групп).

### C. Качество автоклассификации ИИ для новых категорий

- **C1:** не менять `BuildPayload` — новые категории попадут в реестр автоматически (FR-4). Риск: систематическое смешение со схожими категориями, т.к. исторически примеры `Groceries` включали «соусы, специи», а `Meat` — «колбасы» (см. ADR 010, табл. 3.1), а реестр — единственный источник смысла в промте. «Курага» → Fruits, «кетчуп» → Groceries, «сосиски» → Meat — новые категории практически никогда не будут предложены ИИ.
- **C2 (выбрано):** минимальный таргетированный блок эвристик-разграничений в `BuildPayload` для трёх границ (DriedFruits vs Fruits, Sauces/Spices vs Groceries, Sausages vs Meat). Промт остаётся коротким, изменение локализовано в одном файле; полные few-shot примеры и эвристики из ADR 009 — отдельная задача (реализационный долг ADR 009, вне scope этой задачи).

## Решение

### 1. Расширение enum `CommodityCategory` (47 значений, коллизий нет)

Добавить после `Entertainment = 41`, до `Other = 255`:

```csharp
// Продукты (детализация, расширение) — коды 42–45
DriedFruits = 42,
Sauces = 43,
Spices = 44,
Sausages = 45,
```

Гарантии:
- **Только добавление**: существующие коды и имена не меняются; `Other = 255` сохранён.
- **Отсутствие коллизий**: 43 существующих + 4 новых = 47 уникальных кодов (проверяется тестом).
- **Обратная совместимость данных**: `category_id` в PostgreSQL принимает новые int-коды без миграции; `category_name` (≤128) — без миграции.

### 2. `CommodityCategoryHelper`: словарь «категория → группа»

```csharp
private const string ProductsGroup = "Продукты";
private const string TransportGroup = "Транспорт";
private const string OtherGroup = "Прочее";

private static readonly IReadOnlyDictionary<CommodityCategory, string> CategoryGroups = new Dictionary<CommodityCategory, string>
{
    // Продукты (17 категорий)
    { CommodityCategory.Beverages, ProductsGroup },
    { CommodityCategory.Groceries, ProductsGroup },
    { CommodityCategory.Meat, ProductsGroup },
    { CommodityCategory.Poultry, ProductsGroup },
    { CommodityCategory.FishAndSeafood, ProductsGroup },
    { CommodityCategory.Dairy, ProductsGroup },
    { CommodityCategory.Eggs, ProductsGroup },
    { CommodityCategory.Vegetables, ProductsGroup },
    { CommodityCategory.Fruits, ProductsGroup },
    { CommodityCategory.Bakery, ProductsGroup },
    { CommodityCategory.Confectionery, ProductsGroup },
    { CommodityCategory.ReadyMeals, ProductsGroup },
    { CommodityCategory.FastFood, ProductsGroup },
    { CommodityCategory.DriedFruits, ProductsGroup },   // NEW 42
    { CommodityCategory.Sauces, ProductsGroup },        // NEW 43
    { CommodityCategory.Spices, ProductsGroup },        // NEW 44
    { CommodityCategory.Sausages, ProductsGroup },      // NEW 45
    // Транспорт (7 категорий) 31–37
    { CommodityCategory.TollRoads, TransportGroup },
    // ... PublicTransport, RailwayTickets, AirTickets, Taxi, Carsharing, Parking
    // Прочее (4 категории) 38–41
    { CommodityCategory.Tobacco, OtherGroup },
    // ... Telecommunication, Utilities, Entertainment
};

public static string GetGroup(CommodityCategory category)
    => CategoryGroups.GetValueOrDefault(category, "");
```

Поведение для legacy-категорий (0–17) и `Other = 255` **не меняется**: словарь не содержит → `""` (плоский список без `<optgroup>`, решение D1 ADR 010). UI-группировка (источник истины — backend) сохраняется без изменений фронтенда.

### 3. `DisplayNames` — 4 новых записи

Записи добавляются после `Entertainment` (порядок в `GetAll()` = порядок отображения; новые продуктовые категории окажутся в конце optgroup «Продукты», перед «Прочее» — корректно для `groupCategories` в `categoryOptions.tsx`).

### 4. Промт ИИ (`OpenAiCompatibleAiClient.BuildPayload`)

Добавить в user-сообщение блок разграничений (компактно, без раздувания промта):

```
Разграничения:
- Сухофрукты (DriedFruits): изюм, курага, чернослив, финики — не Fruits (свежие фрукты/ягоды).
- Соусы (Sauces) и Приправы (Spices): кетчуп, майонез, соевый соус, специи — не Groceries
  (бакалея — крупы, мука, макароны, сахар, соль, масло, чай/кофе, консервы).
- Колбасные изделия (Sausages): колбаса, сосиски, сардельки, ветчина — не Meat
  (свежее/замороженное мясо).
```

Новые категории в реестре промта появляются автоматически через `CategoryNames` (FR-4) — без хардкода списка; эвристики лишь разводят смыслы перекрывающихся категорий (edge case задачи).

### 5. Контракты и данные

- `GET /api/commodities/categories`, `PUT /api/commodities/{id}/category`, `POST /api/receipts/{id}/categories/suggest`, `PUT /api/receipts/{id}/categories` — **без изменений контрактов** (генерируются из `GetAll()`, валидация через `Enum.IsDefined`).
- PostgreSQL-схема, Go-backend, Telegram-бот, nginx, MongoDB — **не затрагиваются**.

## Обоснование

1. **Исполнение требования заказчика напрямую**: вместо диапазонов кодов — словарь «категория → группа»; 4 новые категории сразу попадают в «Продукты» независимо от кода.
2. **Единственный источник истины сохраняется**: enum + `CommodityCategoryHelper` (ADR 005); UI и промт ИИ подхватывают состав автоматически.
3. **Обратная совместимость и минимальность**: только добавление значений, без перекодировки БД, миграций и правок контрактов; соответствует правилу «только добавление» ADR 010.
4. **KISS/YAGNI**: группа строк-констант + один словарь вместо диапазонов; словарь легко читается, нет ветвлений по кодам.
5. **Качество ИИ**: без эвристик новые категории почти не предлагались бы моделью (перекрытие с Fruits/Groceries/Meat по данным ADR 010); компактный блок разграничений закрывает этот риск с минимальным объёмом изменения (в отличие от полной реализации few-shot из ADR 009 — отдельная задача).

## Компромиссы

- **Словарь «категория → группа» vs «группа → список категорий»**: имя группы повторяется в словаре (17 раз «Продукты») — цена прозрачности; при росте числа групп можно перейти на конфигурацию/БД без смены API `GetGroup`.
- **Эвристики в промте только для 3 границ**: полный few-shot и эвристики ADR 009 остаются за рамками задачи (реализационный долг) — частично неидеальная точность ИИ компенсируется ручной категоризацией администратора (осознанный компромисс, зафиксирован в ADR 009).
- **Коды 42–45 без резервирования между блоками**: при дальнейших расширениях нумерация продолжится серией; группировка от диапазонов больше не зависит (словарь), поэтому рост кодов безопасен.

## Последствия

### Положительные

- Точная аналитика расходов на питание: сухофрукты, соусы, приправы, колбасные изделия выделены из Бакалеи/Фруктов/Мяса.
- `GetGroup` перестаёт зависеть от значений кодов — дальнейшие расширения справочника не потребуют правки группировки.
- Ноль изменений схемы PostgreSQL, Go-backend, бота, nginx; существующие классификации не тронуты.
- Промт ИИ получает новые категории автоматически + таргетированные эвристики для ключевых границ.

### Отрицательные

- Рост справочника до 47 значений (42 в промте без `Undefined`) — промт и UI-список чуть длиннее; компенсируется группировкой `<optgroup>`.
- Changes к `BuildPayload` увеличивают объём промта на ~5 строк — незначительно.

### Риски

- **ИИ всё же путает новые категории с базовыми** (например, «сосиски» → Meat). **Митигация:** эвристики C2; строгая валидация ответа (только имя из enum); ручная коррекция администратора. При сохранении проблемы — отдельная задача на few-shot ADR 009.
- **Пропуск записи в словарях** (`DisplayNames`/`CategoryGroups`) для нового члена → fallback «Не указана»/`""`. **Митигация:** тесты консистентности (каждый член enum имеет отображаемое имя; новые члены имеют группу «Продукты»).
- **Случайное переиспользование кода** при будущих расширениях → коллизия. **Митигация:** тест на уникальность кодов (`GetValues().Distinct().Count() == Length`).
