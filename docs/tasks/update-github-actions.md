# Актуализация GitHub Actions во всех workflow

## Приоритет
blocker

## Проблема
**CI в репозитории не работает прямо сейчас.** 2026-09-23 GitHub окончательно отключил Node 20 в GitHub Actions (Changelog, тег Retired). Все экшены во всех трёх workflow работают на удалённых рантаймах — `node20` у `actions/checkout@v4`, `actions/setup-node@v4`, `actions/setup-dotnet@v4` и всех `docker/*`, и `node12` у `github/codeql-action@v1` (GitHub ранее принудительно поднял их до node20, поэтому поломка проявилась именно 23 сентября).

Следствие: ни сборка образов, ни проверки в PR, ни Code scanning не проходят. Сборка и публикация образов не работают до внедрения этой задачи.

Исторически это не первый случай: обёртки CodeQL на v1 (Node 12) и отсутствие CI-проверки фронтенда (из-за чего линтер молча оставался мёртвым) — предыдущие инциденты того же класса. Актуальные мажорные версии установлены 2026-09-26 по релизам на GitHub API.

| Action | Где используется | Сейчас | Актуально | Рантайм сейчас |
|---|---|---|---|---|
| `actions/checkout` | `codeql-analysis.yml` | v2 | v7 | node20 |
| `actions/checkout` | `build-analytics-image.yml`, `build-backend-image.yml` | v4 | v7 | node20 |
| `actions/setup-node` | `build-analytics-image.yml` | v4 | v7 | node20 |
| `actions/setup-dotnet` | `build-analytics-image.yml` | v4 | v6 | node20 |
| `docker/setup-buildx-action` | оба build-workflow | v3 | v4 | node20 |

| `docker/metadata-action` | оба build-workflow | v5 | v6 | node20 |
| `docker/build-push-action` | оба build-workflow | v5 | v7 | node20 |
| `github/codeql-action` (`init`, `autobuild`, `analyze`) | `codeql-analysis.yml` | v1 | v4 | node12 |

## Цель
Все GitHub Actions во всех workflow переведены на актуальные мажорные версии единой заменой версий, при этом пайплайны сохраняют текущее поведение: те же проверки в PR, те же образы с теми же тегами, работающий Code scanning.

## Пользователи
- Разработчики и ревьюеры — ради зелёных статусных проверок в PR.
- Дежурный по релизу — ради предсказуемости CI, сборки и публикации образов.

## Сценарий использования
1. Разработчик открывает PR с изменениями.
2. В статусных проверках видны те же проверки, что и сейчас: сборка образа аналитики, сборка образа бэка, CodeQL. Все зелёные.
3. После мержа в master образы собираются и публикуются с прежними именами и тегами (`drypa/receipt-collector-analytics`, теги `branch` / `pr` / `sha` / `latest`).
4. Результаты анализа кода доступны в Security → Code scanning.

## Требования
- **FR-1.** Замена только версий экшенов. Триггеры `on:`, условия `if:`, команды, таймауты, секреты и имена шагов не изменяются.
- **FR-2.** Новые шаги не добавляются, кроме тех, что необходимы для совместимости с новой версией экшена (например, если новая версия требует явного права — право добавляется).
- **FR-3.** Никакая функциональность не деградирует. Если новая версия требует жертвы (например, заставляет отказаться от `security-events: write` или выкинуть `autobuild`), этот фрагмент **откатывается точечно** и откладывается отдельной задачей — не делается «любой ценой».
- **FR-4.** Правило отката имеет объективное ограничение, установленное в ADR-025: рабочий откат существует только для `actions/checkout`, `actions/setup-node`, `actions/setup-dotnet` (у них есть соседние мажоры на node24). Для всех `docker/*` и `github/codeql-action` откат невозможен — все предыдущие мажоры работают на отключённых рантаймах. Поэтому при поломке:
  - там, где откат есть, — точечный откат этого экшена;
  - там, где отката нет, — чинить вперёд (это единственный путь к зелёному статусу), а если чинить вперёд нельзя в рамках объёма — завести follow-up-задачу и зафиксировать в отчёте, какая из 9 позиций не выдержала.
- **FR-5.** Требования совместимости новых версий (минимальная версия раннера, необходимые `permissions`, изменения входных параметров) проверяются до и после замены, а не по факту отказа в CI.
- **FR-6.** Замена выполняется тремя отдельными коммитами/изменениями — по одному на каждый workflow (`build-backend-image.yml` → `codeql-analysis.yml` → `build-analytics-image.yml`). Три коммита в одном PR делают частичный откат невозможным.

## Критерии приёмки
- [ ] Все 9 позиций из таблицы переведены на целевые мажорные версии
- [ ] Триггеры, условия `if:` и содержимое шагов не изменены, кроме версий экшенов и необходимых совместимых прав
- [ ] `build-analytics-image.yml` зелёный на PR и на push в master; образ `drypa/receipt-collector-analytics` собирается и публикуется с прежними тегами
- [ ] `build-backend-image.yml` зелёный на PR и на push; образы бэка собираются и публикуются с прежними тегами
- [ ] `codeql-analysis.yml` зелёный на PR и на push; результаты доступны в Security → Code scanning
- [ ] Шаг `Lint frontend` в `build-analytics-image.yml` продолжает работать — обновление `setup-node` не сломало линтер
- [ ] В логах workflow нет предупреждений GitHub о deprecated actions
- [ ] После мержа образы и теги в DockerHub соответствуют ожидаемым (ручная проверка)

## Edge cases
- Смена мажора может требовать новой версии раннера или новых прав доступа — проверяется на первом прогоне, а не по факту отказа
- Обновление CodeQL v1 → v4 может потребовать удаления устаревшего workaround `git checkout HEAD^2`; если без него анализ PR ломается, workaround остаётся и это не блокер
- CodeQL v3+ требует права `security-events: write` — если репозиторий его не имеет, это решается добавлением права (FR-2), а не откатом обновления
- Новая версия экшена может поменять формат вывода или поведение кеша — выводы логов меняются, на результат не влияет
- Авторизация в DockerHub и `push` образа защищены условием `if: github.event_name != 'pull_request'` — обновление `docker/login-action` и `docker/build-push-action` не должно нарушить это поведение
- Экшены `docker/*` требуют Docker-демона на раннере — на `ubuntu-latest` выполняется, но при смене мажора это стоит подтвердить

## Заменяемые документы
Эта задача заменяет `docs/tasks/update-codeql-actions-v3.md` (Draft с 2026-09-06) вместе с ADR-017 и планом `docs/plans/update-codeql-actions-v3.md`: они целятся в `codeql-action` v3, тогда как актуальна v4. Старые документы остаются в репозитории для истории и помечаются как заменённые этой задачей; отдельная задача на CodeQL не заводится.

## Вне объёма
- Изменение логики пайплайнов (последовательности шагов, триггеров, условий)
- Кеширование npm, добавление новых проверок в CI
- Правка Dockerfile, кода приложения и конфигурации сервисов
- Обновление рабочих версий Node, .NET SDK, Go и прочих инструментов в образах
- Пиннинг экшенов на конкретный SHA вместо мажорного тега
- Перевод на `zizmor`/`actionlint` и другие линтеры workflow

## Решения заказчика
- Обновляем **все** экшены во **всех** workflow разом, а не по одному: правки в одних и тех же файлах, проверка общая
- CodeQL включается в эту же задачу, несмотря на наличие отдельной открытой задачи
- При поломке, которую не удаётся починить, изменения **откатываются и откладываются** отдельной задачей. Уточнение после исследования ADR-025: откат технически возможен только для 3 из 9 позиций, для остальных единственный путь — чинить вперёд (FR-4)
- Приоритет повышен до **blocker** после установления факта отключения Node 20 в GitHub Actions 2026-09-23
