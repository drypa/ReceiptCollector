# Категория товаров по умолчанию для магазина (merchant)

## Приоритет
high

## Проблема
Администратору приходится очень долго вручную категоризировать товары по всем
историческим чекам. При этом многие магазины логично «мапятся» на одну категорию:
обеды в столовой — «Готовая еда», автосервис — «Автотовары», фитнес-клуб —
«Фитнес и спорт». Сейчас такой возможности нет: каждый товар из нового чека
проходит через кэш / precategorized / AI suggest или категоризируется вручную.

## Цель
Дать администратору возможность задать магазину (merchant) категорию товаров по
умолчанию. Все позиции из чеков этого магазина автоматически получают эту
категорию — при поступлении новых чеков сразу, для накопленных — по кнопке.
Это ускорит категоризацию и в перспективе может использоваться как подсказка
для ИИ (в текущей задаче — не входит в объём).

## Пользователи
Только администратор (управление настройкой, запуск дожима категорий).
Обычные пользователи видят только результат — готовые категории товаров.

## Сценарий использования
1. Администратор в разделе `/merchants` задаёт магазину параметр «категория
   товаров по умолчанию» (отдельное поле, не пересекающееся с категорией самого
   магазина). Магазин идентифицируется уникальным идентификатором.
2. Редактирование магазина и настройка доступны также в разделе «Детали чека».
3. При поступлении нового чека от магазина с настроенной категорией по умолчанию
   все его позиции без существующей категории сразу получают эту категорию,
   с пометкой источника `merchant-default`.
4. Для исторических позиций администратор в «Детали чека» нажимает кнопку
   «категоризировать существующие» (для конкретного магазина): заполняются
   категории только у позиций этого магазина **без категории**.
5. Изменение/снятие дефолтной категории не влияет на уже сохранённые товары —
   только на будущие чеки.

## Критерии приёмки
- [ ] В `/merchants` можно задать и изменить категорию товаров по умолчанию
      для магазина; то же доступно в «Детали чека».
- [ ] Параметр хранится отдельно и не пересекается с категорией самого магазина.
- [ ] Новые чеки от магазина с дефолтной категорией автоматически категоризируются
      ею при поступлении.
- [ ] Кнопка «категоризировать существующие» в «Детали чека» обрабатывает только
      позиции конкретного магазина без категории.
- [ ] Порядок приоритета: ручная категория → категория магазина по умолчанию →
      кэш → precategorized → AI suggest (дефолт магазина бьёт машинные варианты,
      но не ручные).
- [ ] Ручные категории никогда не перезаписываются дефолтом магазина.
- [ ] Категория, проставленная дефолтом магазина, помечается отдельным
      источником (`merchant-default`) и отличима от `ai`, `precategorized`, manual.
- [ ] Магазины без настроенной дефолтной категории работают по текущему потоку
      (кэш → precategorized → AI / вручную) без изменений.
- [ ] Изменение/снятие дефолта не меняет уже сохранённые товары.
- [ ] Покрыто unit-тестами; ручная проверка через UI.

## Edge cases
- У магазина не задана дефолтная категория → обычный поток категоризации.
- У товара уже есть ручная категория → не трогаем (и при импорте новых чеков,
  и при дожиме кнопкой).
- У товара уже есть **сохранённая** категория (любая: ручная, подтверждённая из precategorized,
  проставленная ранее) — **не перезаписывается**. Дефолт магазина перекрывает только машинные
  *предложения* в цепочке suggest (порядок: существующая → дефолт магазина → кэш → precategorized → AI).
  Уточнение принято заказчиком 2026-11-06 по ADR-032 (вариант «дефолт выше существующей» отклонён —
  защита уже внесённого вручную и подтверждённого труда).
- Админ снял/поменял дефолтную категорию → старые товары остаются как были;
  новые чеки получают новую категорию; повторный запуск кнопки дожимает только
  позиции без категории.
- Дефолтная категория магазина указывает на категорию, которой нет в справочнике
  (удалена/переименована) → валидация при установке (выбирать можно только
  существующую категорию); поведение при удалении категории из справочника
  определяет архитектор (например, дефолт сбрасывается).
- Магазин без идентификатора в чеке (нет привязки к merchant) → дефолт не
  применяется, обычный поток.

## Зависимости
- Существующая модель merchant и справочник категорий товаров (Analytics).
- Существующий поток категоризации: существующая категория → кэш →
  precategorized → AI suggest (ADR 009, 019, 027, 028, 030).
- UI-разделы: `/merchants`, «Детали чека» (кнопка для дожима по магазину).

## Вне объёма (не в этой задаче)
- Передача дефолтной категории магазина в качестве подсказки в AI-запрос.
- Глобальная кнопка «прогнать все магазины с настроенной категорией».
