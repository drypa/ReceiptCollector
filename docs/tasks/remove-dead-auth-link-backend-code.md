# Задача: Удалить мёртвый код генерации auth-ссылки в backend (`users/link`)

- **Статус:** открыта (follow-up к ADR-016; ожидает реализации)
- **Автор:** менеджер проекта
- **Дата создания:** 2026-08-27
- **Приоритет:** низкий (чистка кода, не влияет на функциональность)
- **Исполнитель:** @software-architect (техническое решение) → @senior-developer (реализация)

## 1. Бизнес-задача

В backend-сервисе (Go, сбор чеков с nalog.ru) существует **мёртвый код** — пакет
`backend/users/link/` и связанные с ним поля/переменные. Этот код задумывался для
вызова эндпоинта генерации auth-ссылки (`GET /api/users/auth/link`), но в текущей
архитектуре **нигде не используется** (эндпоинт теперь принадлежит Analytics и
вызывается Telegram-ботом, см. ADR-016). Требуется удалить мёртвый код, чтобы
упростить сопровождение и убрать ложное впечатление, что backend генерирует auth-ссылки.

Это follow-up к задаче «Закрыть эндпоинт генерации auth-ссылки от внешнего мира»
([ADR-016](../adr/016-close-auth-link-from-public-nginx.md)) — там чистка была вынесена
в отдельную задачу вне основного scope.

## 2. Ценность для заказчика

- **Снижение стоимости сопровождения** — меньше кода с неоднозначным назначением,
  который вводит в заблуждение при ревью и будущих доработках: читая `Processor`,
  разработчик больше не подумает, что backend выдаёт auth-ссылки.
- **Снижение поверхности атаки / уязвимостей** — удаляется неиспользуемый HTTP-клиент,
  который при активации мог бы обращаться к устаревшим URL (в т.ч. `OPEN_URL`,
  «протекавший» через фронтенд-адрес) без реальной надобности.
- **Чистота и предсказуемость** — меньше кода = меньше точек отказа, проще проходить
  security-аудиты (CodeQL) и ревью PR.
- **Без изменений для пользователя** — код мёртвый, удаление не влияет на поведение API,
  Telegram-бота или фронтенда.

## 3. Текущая ситуация (контекст) — что именно мертвое

Проверено по коду (grep по репозиторию):

- `backend/users/link/client.go` — пакет `users/link`, структура `Client` с методом
  `GetUserAuthLink`. Метод **нигде не вызывается** (объявление и определение — единственные
  упоминания). Пакет содержит только этот файл.
- `backend/users/processor.go`:
  - поле `client *link.Client` в структуре `Processor` (строка 19) — **не используется**
    ни одним методом процессора;
  - параметр `client *link.Client` в конструкторе `NewProcessor` (строка 23) и присваивание
    `client: client` в `&Processor{...}` (строка 29);
  - импорт `"receipt_collector/users/link"` (строка 10).
  - (Единственные употребления `.client` в пакете — не связаны: `ClientSecret: p.clientSecret`
    и `repository.client` в `users/repository.go` — их НЕ трогать.)
- `backend/main.go`:
  - `var openUrl = os.Getenv("OPEN_URL")` (строка 36) — используется только для linkClient;
  - `linkClient := link.NewClient(openUrl)` (строка 91) и передача `linkClient` в
    `users.NewProcessor(...)` (строка 92);
  - импорт `"receipt_collector/users/link"` (строка 25).

Тесты не затрагивают пакет `users/link` (проверено: отсутствие ссылок в `_test.go`).

## 4. Объём работ (scope)

1. Удалить файл `backend/users/link/client.go` (целиком пакет `users/link`).
2. В `backend/users/processor.go`:
   - убрать поле `client *link.Client` из `Processor`;
   - убрать параметр `client *link.Client` из `NewProcessor` и присваивание;
   - убрать импорт `"receipt_collector/users/link"`.
3. В `backend/main.go`:
   - убрать `var openUrl = os.Getenv("OPEN_URL")`;
   - убрать `linkClient := link.NewClient(openUrl)` и поправить вызов
     `users.NewProcessor(...)` (без linkClient);
   - убрать импорт `"receipt_collector/users/link"`.
4. (Решение об объёме — за архитектором) Переменная `OPEN_URL` после удаления кода больше
   не используется в `backend/`. Решить, обновлять ли связанные упоминания:
   `_.env`, `.env.example`, `README.md`, `dev-run.sh`, `docs/tasks/dev-debug-run-script.md`,
   `docs/plans/dev-debug-run-script.md`. Допустимо оставить только документацию или
   почистить её отдельно — главное — удалить код backend.

## 5. Критерии приёмки

1. Пакет `backend/users/link/` полностью удалён (каталог отсутствует).
2. В коде `backend/` не осталось ссылок на `users/link`, `link.NewClient`, `link.Client`,
   `GetUserAuthLink`, `linkClient`, `openUrl` (проверить: `grep -rn "users/link\|link\.NewClient\|link.Client\|GetUserAuthLink\|linkClient\|openUrl" backend/` → только ожидаемые/пустые).
3. `Processor` больше не содержит поле/параметр `client` и не импортирует `users/link`.
4. `cd backend && go build ./...` и `cd backend && go test ./...` проходят успешно.
5. Сборка Docker-образа backend проходит успешно.
6. Поведение API/бота/фронтенда не изменилось (мёртвый код не вызывался).

## 6. Вне объёма (out of scope)

- Изменение логики живой аутентификации в Analytics или боте.
- Удаление/смена других пакетов, полей, env-переменных, помимо описанных в разделе 4.
- Любые изменения сетевой конфигурации nginx/docker (задача ADR-016 уже реализована).

## 7. Открытые вопросы / риски

1. **Судьба `OPEN_URL` в env/скриптах/доке.** После удаления кода backend `OPEN_URL`
   становится неиспользуемой. Целесообразность удаления из `.env`, `.env.example`,
   `README.md`, `dev-run.sh` и docs-файлов — решение архитектора; риск затрагивает
   только dev-скрипты/документацию, не прод-функциональность.
2. **Регрессия импортов.** Если после удаления где-то останется неиспользуемый импорт,
   Go-сборка упадёт — критерий 4 это поймает.
3. **Corollary (не задача этой фичи):** клиент бота `bot/analytics/client.go` использует
   тот же эндпоинт `auth/link` и остаётся живым — его НЕ трогать.
