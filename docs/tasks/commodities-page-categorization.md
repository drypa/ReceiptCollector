# Автоматическая категоризация товаров на странице «Товары»

## Приоритет
medium

## Проблема
Страница «Товары» (`/commodities`) показывает плоский список всех позиций всех чеков пользователя с пагинацией и фильтром по категории, но автоматической категоризации на ней нет. Администратору, который размечает товары, приходится для каждой позиции открывать детали чека, запускать там категоризацию и возвращаться — на объёме в десятки и сотни позиций это нерабочая рутина. При этом работа идёт именно «по экрану»: администратор видит 5 строк, размечает их и идёт дальше.

Дополнительное ограничение: синхронная категоризация 10 позиций не всегда укладывается в таймаут, поэтому «один длинный запрос на всю страницу» ненадёжен — ожидание не должно превращаться в ошибку и потерю работы.

## Цель
Дать администратору на странице «Товары» сценарий «Категоризировать → проверить → сохранить», аналогичный странице «Детали чека», но с единицей работы «видимая страница списка» и с устойчивостью к таймаутам: результаты приходят постепенно, сохранить можно в любой момент, частичный сбой не ломает страницу.

## Пользователи
Администраторы Analytics (колонка «Категория» и ручная правка категории уже доступны только им). Для не-админов поведение страницы не меняется.

## Решения заказчика
1. Категоризируются **только строки, отображённые на текущей странице**.
2. Основной сценарий — **страницей**, а не построчно: один запуск на страницу, проверка и правка в таблице, одно сохранение. Построчный запуск остаётся только как «повторить для этой строки».
3. Результаты по странице приходят **постепенно, порциями по ~5 названий**; «Сохранить категории» доступна в любой момент — сохраняется уже полученное, неразобранные строки остаются «не определена». Таймаут деградирует до частичного результата, а не до ошибки.
4. Пустое значение в селекте = **«категорию не трогаем»** (не сброс в `null`).
5. В режиме проверки пагинация, выбор размера страницы и фильтр категории **заблокированы** с подсказкой «Сначала сохраните или отмените изменения».
6. После сохранения под фильтром «Без категории» / «Категория «Не указана»» размеченные строки уходят из фильтра, а страница **сама наполняется следующими** строками; если страница опустела и это не первая — переход на предыдущую доступную.
7. Если ИИ не настроен/недоступен, категоризация **всё равно запускается**: работают кэш прошлых чеков и очередь предкатегорий, остальное помечается «не определена». (На «Деталях чека» сейчас 503 — это поведение там не меняем.)
8. Подпись-источник показывается **у каждой строки**, в том числе при повторяющихся названиях.
9. Тост после сохранения: «Сохранено категорий: N», где N — **только реально изменённые** при этом сохранении строки.
10. Дефолт и общий селектор размера страницы **не меняем** (по-прежнему общий для «Чеков» и «Товаров», дефолт 10).
11. Область задачи — **только** `/commodities`; страницу «Детали чека» не трогаем (выравнивание поведения — отдельная задача, если понадобится).

## Сценарий использования

### Happy path (рабочий цикл администратора, 5 строк на странице)
1. Админ открывает «Товары», фильтр «Без категории», размер страницы 5.
2. В шапке рядом с фильтром видит кнопку «Категоризировать страницу (5)», где 5 — число строк без категории на странице. Если таких строк нет — кнопка неактивна с подсказкой «На этой странице нет товаров без категории».
3. Клик — таблица переходит в режим проверки: в колонке «Категория» появляются выпадающие списки; строки, у которых категория уже была, показаны со своим значением и подписью «уже присвоена» (в ИИ не уходят); строки без категории заполняются по мере готовности с подписью источника: «по прошлым чекам» / «из очереди предкатегорий» / «предложено ИИ» / «не определена». В шапке — прогресс «Определяем категории… X из Y».
4. Админ просматривает предложения и при необходимости меняет значения в списках.
5. «Сохранить категории» → возврат в обычный вид, таблица перезагружает текущую страницу, в колонке появляются названия категорий, тост «Сохранено категорий: N» (N — изменённые строки).
6. Под фильтром «Без категории» размеченные строки исчезают, на их место поднимаются следующие 5. Админ повторяет шаги 2–5, не трогая пагинацию.

### Отмена
Кнопка «Отмена» выбрасывает черновик без записи; таблица возвращается в обычный вид, пагинация и фильтр разблокируются.

### Длинная страница (20/50/100 строк)
После запуска сразу виден прогресс и постепенно заполняющиеся строки. Админ может сохранить в любой момент — сохраняется уже предложенное; строки «не определена» можно дозапустить точечно, не перезапуская всю страницу.

### Ошибки
- ИИ недоступен → запуск всё равно происходит, всё, что есть в кэше/очереди, предлагается; остальное — «не определена» (с предупреждением, что ИИ недоступен).
- Сбой по конкретному названию → строка «не определена», текст ошибки в подсказке, остальные строки обрабатываются; сохранение доступно.
- Ошибка сохранения (сеть/сервер) → ошибка тостом, черновик сохраняется, можно повторить сохранение.

## Критерии приёмки
- [ ] Кнопка «Категоризировать страницу (N)» отображается только администраторам; N = число строк без категории на текущей странице; при N = 0 кнопка неактивна с пояснением.
- [ ] Категоризация запрашивается **только для строк текущей страницы**; строки других страниц не затрагиваются.
- [ ] Режим проверки: в каждой строке селект категорий; для ранее категоризированных строк значение предзаполнено и помечено «уже присвоена»; для остальных показан источник предложения; подпись источника отображается у каждой строки, включая повторяющиеся названия.
- [ ] Одинаковые названия внутри страницы получают одинаковое предложение и не приводят к повторным вызовам ИИ по одному и тому же названию.
- [ ] Результаты отображаются по мере готовности (порциями ~5 названий), прогресс виден; страница не «висит» до полного завершения.
- [ ] «Сохранить категории» доступна во время и после обработки; сохраняется уже полученный результат; неразобранные строки остаются без изменений.
- [ ] Пустое значение в селекте не сбрасывает ранее существующую категорию (семантика «не трогаем»).
- [ ] В режиме проверки пагинация, размер страницы и фильтр категории заблокированы с подсказкой; после сохранения/отмены — разблокированы.
- [ ] После успешного сохранения: таблица перезагружает текущую страницу, тост «Сохранено категорий: N» с числом изменённых строк, порядок строк не «прыгает» (сортировка по дате и названию не зависит от категории).
- [ ] Под фильтром «Без категории»/«Не указана» после сохранения размеченные строки уходят из выборки, страница наполняется следующими; пустая последняя страница приводит к переходу на предыдущую доступную; счётчик «Найдено товаров» обновляется.
- [ ] При пустом/недоступном ИИ категоризация запускается и отдаёт результаты из кэша прошлых чеков и очереди предкатегорий; пользователь получает понятное сообщение о недоступности ИИ.
- [ ] Сбой по отдельному названию не блокирует остальные строки и сохранение.
- [ ] Повтор запуска на уже размеченной странице работает корректно (все строки «уже присвоена», кнопка неактивна при отсутствии строк без категории).
- [ ] Не-администраторы не видят кнопку и не получают доступа к операции (серверная проверка прав).
- [ ] Автотесты Analytics проходят (`cd Analytics && dotnet test`); новое поведение покрыто тестами.
- [ ] Ручной прогон на dev-стенде: 5 строк, фильтр «Без категории», конвейер из 2–3 страниц, сценарий с недоступным ИИ.

## Edge cases
- **Страница целиком уже размечена** — кнопка неактивна, режим проверки не открывается.
- **Страница опустела после сохранения** под фильтром «Без категории» (последняя страница) — переход на предыдущую доступную; пустой список не показывается как ошибка.
- **Повторяющиеся названия** (одно название в 5+ строках) — одно предложение на все строки, подпись у каждой; правка значения в одной строке не обязана автоматически менять остальные (поведение подтверждается на приёмке).
- **Пользователь изменил размер страницы/фильтр в момент запуска** — элементы управления уже заблокированы; гонки быть не должно.
- **Смена страницы в режиме проверки невозможна** — черновик не теряется и не сохраняется частично «не туда».
- **ИИ отвечает дольше таймаута по части названий** — частичный результат + «не определена» + точечный повтор; ошибки «сервер не успел» с потерей введённого не должно быть.
- **Одновременная работа фоновой предкатегоризации** (ADR-027) — не должна приводить к конфликтам: в `commodities` пишет только подтверждение администратора.
- **Категория изменена вручную в другой вкладке** — после перезагрузки страницы отображается актуальное значение; при сохранении допускается «последняя запись побеждает».
- **Позиция без названия/пустое название** — строка не ломает запуск, помечается «не определена».

## Зависимости
- Существующий механизм категоризации Analytics: приоритет «категория позиции → in-memory кэш → очередь предкатегорий → ИИ» (ADR-009, ADR-019, ADR-027) и справочник категорий (`GET /api/commodities/categories`).
- Права администратора и текущая owner-scoped выборка позиций (`GET /api/commodities`).
- Фронтенд страницы «Товары» и существующий компонент уведомлений (тосты).
- Ограничение по времени ответа на стороне прокси/ИИ: категоризация страницы не должна упираться в единый длинный запрос (см. решения заказчика 3 и 11).

## Не входит в объём
- Изменение страницы «Детали чека» (в т.ч. её поведение при пустом `AI:BaseUrl` и семантика тоста).
- Категоризация товаров за пределами текущей страницы («разметить всё» одним действием).
- Изменение дефолтного/глобального размера страницы.
- Изменение справочника категорий.
