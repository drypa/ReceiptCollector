# Порционная категоризация товаров чека с бюджетом запроса

## Приоритет
medium

## Проблема
Автоматическая категоризация на странице «Детали чека» обрабатывает **все** позиции чека одним синхронным запросом (`POST /api/receipts/{id}/categories/suggest`). Время ответа линейно зависит от числа уникальных названий и ограничено только таймаутом отдельного вызова модели (`AI:Timeout`, в текущем `appsettings.json` — 80 с) при ограничении параллельности `AI:Concurrency = 3`.

Для чека в 25–30 позиций суммарное время выходит за `proxy_read_timeout` nginx (120 с в `nginx.prod.conf`), прокси отдаёт 504, и пользователь **не получает ни одной категории** — при том что часть позиций давно определилась бы из кэша прошлых чеков или очереди предкатегорий. Комментарий про синхронную категоризацию рядом с `proxy_read_timeout` в конфигурации nginx подтверждает: в это упирались и раньше.

Аналогичная проблема на странице «Товары» уже решена (ADR-028: дробление на порции, серверный бюджет запроса, частичный результат). Для чека решение не применялось сознательно — тогда была зафиксирована область «только `/commodities`» (C11 в `docs/tasks/commodities-page-categorization.md`).

## Цель
Сделать категоризацию чека устойчивой к таймаутам так же, как на странице «Товары»: предложения приходят порциями по мере готовности, сохранить можно в любой момент, частичный сбой или таймаут не означают потерю всей работы. Существующий сценарий «весь чек одним запросом» и все текущие контракты сохраняются.

## Пользователи
Все аутентифицированные пользователи, которые категоризируют чек (не только администраторы — доступ не должен сузиться).

## Решения заказчика
1. **Тот же бюджет, что и на «Товарах»**: используется существующая опция `CommodityBatchCategorization__SuggestTimeout` (по умолчанию `00:00:25`). Новой конфигурации не заводим.
2. **Чек дробится на порции** по ≤ 5 уникальных названий; запросы выполняются последовательно; сервер не хранит состояние между запросами.
3. **`503` при пустом `AI:BaseUrl` остаётся как есть** — поведение чека при незаблокированном/не настроенном ИИ не меняется (в отличие от страницы «Товары», где `200 + aiAvailable = false`).
4. Предложения отображаются **по мере готовности** с прогрессом «Определяем категории… X из Y»; режим проверки не блокируется ожиданием последней порции.
5. **«Сохранить категории» доступна в любой момент**: сохраняется то, что видит пользователь; неразобранные позиции остаются без категории, для них работает точечный повтор.
6. **Семантика сохранения не меняется**: пустой селект = сброс категории (reset), как сейчас; текст и логика тоста «Сохранено категорий: N» остаются прежними (в отличие от страницы «Товары», где считается только изменённое).
7. **Кнопка «Повторить»** для позиции со статусом «не определена»/ошибкой — с правами как у текущей категоризации чека (не только для админов).
8. **Защита черновика**: предупреждение браузера при уходе со вкладки (`beforeunload`) и отмена незавершённых запросов; переходы внутри приложения (кнопка «← Назад к списку чеков», смена раздела) не блокируются.
9. **Приёмка — только автотесты** (`cd Analytics && dotnet test`), без ручной проверки на dev-стенде.

## Сценарий использования

### Happy path: большой чек (25–30 позиций)
1. Пользователь открывает чек и нажимает «Категоризировать».
2. Таблица сразу переходит в режим проверки: в каждой строке селект категорий; позиции, у которых категория уже была, предзаполнены с подписью «уже присвоена» и в обработку не входят.
3. Остальные позиции заполняются по мере готовности порциями по ≤ 5 уникальных названий; над таблицей прогресс «Определяем категории… X из Y»; подпись-источник у каждой строки.
4. Пользователь правит что нужно (в том числе может оставить селект пустым — это сброс категории) и нажимает «Сохранить категории», не дожидаясь конца обработки.
5. Сохраняется видимое; черновик закрывается; тост в прежней формулировке; позиции без предложения остаются без категории.

### Таймаут или сбой модели по части позиций
Часть позиций помечается «не определена» с текстом ошибки в подсказке; остальные сохраняются как обычно; для неудавшейся позиции доступна кнопка «Повторить», которая запрашивает предложение только для неё, без перезапуска всего чека.

### Отмена и уход со страницы
«Отмена» выбрасывает черновик без записи. При уходе со вкладки браузера во время проверки пользователь получает стандартное предупреждение; in-flight запросы отменяются и их ответы не применяются.

### ИИ не настроен
Поведение как сейчас: запрос отвергается с `503`, пользователь получает прежнее сообщение об ошибке. Порционная логика в этом случае не запускается.

## Критерии приёмки
- [ ] Категоризация чека выполняется порциями по ≤ 5 уникальных названий; предложения отображаются по мере готовности, прогресс «X из Y» виден.
- [ ] Время ответа одного запроса ограничено существующей опцией `CommodityBatchCategorization__SuggestTimeout`; новой конфигурации не появилось.
- [ ] По истечении бюджета незавершённые позиции получают статус «не определена» с текстом ошибки, ответ — успешный с частичным результатом; HTTP 504 со стороны прокси больше не является штатным исходом для большого чека.
- [ ] «Сохранить категории» активна во время обработки и сохраняет видимое; неразобранные позиции остаются без категории.
- [ ] Для позиции «не определена»/с ошибкой доступна кнопка «Повторить»; повтор запрашивает предложение только для этой позиции и не меняет уже отредактированные пользователем значения.
- [ ] Права на повтор не уже, чем у текущей категоризации чека (не-администратор может повторить).
- [ ] Пустой селект по-прежнему сбрасывает категорию; текст и подсчёт тоста «Сохранено категорий: N» не изменились.
- [ ] `POST /api/receipts/{id}/categories/suggest` при пустом `AI:BaseUrl` по-прежнему отвечает `503`.
- [ ] `PUT /api/receipts/{id}/categories` не изменён (контракт и reset-семантика).
- [ ] Существующий вызов «весь чек одним запросом» остаётся работоспособным: поведение не меняется для клиентов, которые запрос не дробят.
- [ ] Приоритет «категория позиции → кэш прошлых чеков → очередь предкатегорий → ИИ» и дедупликация по нормализованному названию сохранены; реализация переиспользует общий конвейер (`ICommodityCategoryResolver`) и бюджет из ADR-028, а не дублирует их.
- [ ] Отмена запроса клиентом (уход, «Отмена», размонтирование) прерывает обработку целиком и не отображается как частичный результат.
- [ ] При уходе из вкладки в режиме проверки черновика показывается предупреждение браузера; ответы отменённых запросов не применяются.
- [ ] Страница «Товары» (ADR-028) не регрессировала: её сценарий и тесты работают без изменений.
- [ ] Автотесты проходят: `cd Analytics && dotnet test`, включая существующие тесты категоризации чека **без правок утверждений** (допустима только механическая правка сборки зависимостей).

## Edge cases
- **Очень большой чек (100+ позиций)**: десятки последовательных порций; сохранение доступно с первой же порции; страница не блокируется.
- **Все позиции чека уже категоризированы**: порций нет, режим проверки открывается сразу с подписями «уже присвоена».
- **Одинаковые названия в чеке** (например, 3× «Молоко 3,2%»): одно предложение на все строки, подпись у каждой; повторный вызов ИИ по тому же названию не выполняется.
- **Позиция с пустым наименованием**: не уходит в ИИ, помечается «не определена», не ломает порцию.
- **Чек изменён/удалён в другой сессии во время проверки**: сохранение не должно задеть чужие или несуществующие позиции (owner-проверка), поведение при устаревших id — не тихий успех.
- **Пользователь вручную отредактировал позицию, после которой пришла поздняя порция**: пришедшее предложение не перезаписывает ручной ввод.
- **Пользователь нажал «Сохранить», потом быстро «Отмена»/ушёл**: ответы отменённых запросов не применяются, двойного сохранения нет.
- **Прокси или модель отдают 5xx по отдельной порции**: остальные порции продолжают обрабатываться, строки порции помечаются «не определена».
- **Одновременная фоновая предкатегоризация** (ADR-027): чтение очереди не должно приводить к записи в неё; в `commodities` пишет только подтверждение пользователя.

## Зависимости
- ADR-009 (категоризация товаров чека), ADR-019 (in-memory кэш), ADR-027 (очередь предкатегорий), ADR-028 (порционность и бюджет запроса на странице «Товары») — решение обязано переиспользовать общий конвейер и бюджет, а не создавать второй.
- Опция `CommodityBatchCategorization:SuggestTimeout` (уже реализована, проброшена в `docker-compose.yml` и `.env.example`).
- Ограничение `proxy_read_timeout` nginx (120 с) — бюджет обязан оставаться существенно меньше.
- Фронтенд страницы «Детали чека» и существующий компонент тостов.

## Не входит в объём
- Изменение `PUT /api/receipts/{id}/categories` (в т.ч. reset-семантики и подсчёта тоста).
- Изменение поведения при пустом `AI:BaseUrl` на чеке (`503` сохраняется).
- Новые конфигурационные опции.
- Изменения страницы «Товары», справочника категорий, миграции БД и конфигурации nginx.
