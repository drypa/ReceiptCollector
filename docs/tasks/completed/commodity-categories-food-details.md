# Добавление новых категорий товаров группы «Продукты»

## Приоритет
medium

## Проблема
В справочнике категорий товаров группы «Продукты» не хватает конкретных категорий для ряда часто встречающихся товаров:

- **сухофрукты** (изюм, курага, чернослив и т.п.) — сейчас попадают в «Бакалею»/«Фрукты» без конкретики;
- **соусы** (кетчуп, майонез, соевый соус и т.п.) — сейчас относятся к «Бакалее»;
- **приправы/специи** — сейчас относятся к «Бакалее»;
- **колбасы/сосиски/сардельки** — отдельной категории нет, сейчас относятся к «Мясу».

Пользователю при ручной классификации товаров на UI не хватает конкретики: реальные покупки не ложатся в названия нынешних категорий, что размывает аналитику расходов на питание.

## Цель
Добавить 4 новые категории в группу «Продукты»: **Сухофрукты**, **Соусы**, **Приправы**, **Колбасные изделия** (одна категория для колбас/сосисок/сарделек). Новые категории должны быть доступны при ручной классификации на UI и учитываться автоматической классификацией через ИИ. Уже классифицированные товары не переклассифицируются.

## Пользователи
Пользователи с доступом к категоризации товаров на UI сервиса Analytics (ручная классификация).

## Текущее состояние (AS-IS)
- `CommodityCategory` — enum в `Analytics/src/ReceiptCollector.Analytics.Domain/Modules/Commodities/CommodityCategory.cs`; продукты детализированы кодами 18–30 (`Beverages=18` … `FastFood=30`), заняты коды до 41, `Other = 255`.
- `CommodityCategoryHelper.GetGroup()` — определяет группу через `switch` по **диапазонам кодов** (`>= Beverages and <= FastFood => "Продукты"`). Новые коды (начиная с 42) в существующий диапазон 18–30 не попадут.
- Список категорий для UI и для промта ИИ генерируется из `CommodityCategoryHelper.GetAll()`: `GET /api/commodities/categories` (фронт — `CommodityTable.tsx`), промт ИИ — `CategoryNames` в `CommodityCategorizationService.cs` (имена enum без `Undefined`). Новые категории попадут в оба источника автоматически при добавлении в enum.
- Категория товара хранится в PostgreSQL denormalized: `commodities.category_id` (int?) + `commodities.category_name` (varchar(128)).

## Сценарий использования
1. Пользователь открывает UI классификации (страница товаров в Analytics).
2. Выбирает товар, например «курага», «кетчуп», «орегано» или «сосиски».
3. В списке категорий группы «Продукты» видит и выбирает новую категорию: «Сухофрукты», «Соусы», «Приправы» или «Колбасные изделия».
4. Категория сохраняется; товар отображается в фильтре/списке по выбранной категории.
5. Автоклассификация (ИИ) при выборе категории для подходящего товара также может предложить одну из новых категорий.

## Функциональные требования (FR)
- FR-1: В enum `CommodityCategory` добавлены 4 новых значения: **Сухофрукты**, **Соусы**, **Приправы**, **Колбасные изделия** — с корректными русскими отображаемыми именами и примерами товаров.
- FR-2: Все 4 новые категории принадлежат группе **«Продукты»** (группировка в UI, `<optgroup>`).
- FR-3: Новые категории доступны для ручной классификации на UI (`GET /api/commodities/categories` + `PUT /api/commodities/{id}/category` без изменений контракта).
- FR-4: Промт ИИ автоматически включает новые категории (генерируется из `GetAll()`, без ручного хардкода).
- FR-4.1: В промт ИИ добавлен блок эвристик-разграничений новых категорий от базовых (Сухофрукты ≠ Фрукты, Соусы/Приправы ≠ Бакалея, Колбасные изделия ≠ Мясо) — решение заказчика от 2026-09-24.
- FR-5: Существующие классификации товаров не изменяются.

## Критерии приёмки
- [ ] 4 новые категории («Сухофрукты», «Соусы», «Приправы», «Колбасные изделия») присутствуют в enum `CommodityCategory` и в справочнике `GET /api/commodities/categories` с корректными русскими именами
- [ ] Все новые категории отображаются в группе «Продукты» в UI (при ручной классификации)
- [ ] Ручная классификация товара в новую категорию работает (PUT принимает, категория сохраняется и отображается в списке/фильтре)
- [ ] При автоклассификации промт ИИ содержит новые категории (проверяется по коду/тестам формирования `CategoryNames`)
- [ ] В промте ИИ присутствуют эвристики-разграничения новых категорий от базовых (проверяется тестом на содержание эвристик в теле запроса)
- [ ] Существующие категории и их коды не изменены; старые классификации не тронуты
- [ ] Реализован словарь/маппинг «категория → группа» вместо switch по диапазонам кодов в `GetGroup` (пожелание заказчика)
- [ ] Проект Analytics собирается, тесты проходят (`cd Analytics && dotnet test`); обновлены тесты, зависящие от состава/количества категорий и групп

## Edge cases
- Новые коды enum — только **добавление** без переиспользования существующих значений (коды > 41, без коллизий); `Other = 255` сохраняется
- Существующие товары с `category_id`-ами, ранее попадавшими в «Бакалею»/«Мясо», не переклассифицируются автоматически
- Промт ИИ при росте числа категорий не должен деградировать: новые категории не должны дублировать смысл существующих (`Groceries`/`Fruits`/`Meat` — пересмотреть примеры/эвристики в промте при необходимости)
- UI: группа «Продукты» не должна ломаться при добавлении категорий с кодами вне старого диапазона 18–30
- Кэш категорий (`ICommodityCategoryCache`) инициализируется из БД — данные со старыми категориями не должны вызывать ошибок

## Зависимости
- Сервис Analytics (.NET) — `CommodityCategory.cs`, `CommodityCategoryHelper`, `CommodityCategorizationService`, `CommodityEndpoints`
- Затрагивается только Analytics; Go-backend, Telegram-бот, PostgreSQL-схема и nginx **не меняются**
