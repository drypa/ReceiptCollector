# Задача: Раздел «Товары» (Commodities) в модуле Analytics

## Бизнес-ценность для заказчика

Пользователи хотят видеть не только сводку по чекам, но и детализированный список всех купленных товаров. Это позволяет:
- Анализировать, на что именно тратятся деньги (не только общая сумма чека, но и отдельные товары)
- Быстро находить конкретный товар и видеть, где и когда он был куплен
- Администраторам — классифицировать товары по категориям для последующей аналитики и группировки расходов

## Описание бизнес-задачи

Реализовать в веб-интерфейсе модуля Analytics новый самостоятельный раздел «Товары», который будет доступен аутентифицированным пользователям через боковое меню (sidebar). Раздел должен показывать плоскую таблицу всех товаров пользователя с детальной информацией по каждому товару. Для пользователей с ролью администратора должна быть возможность указать/изменить категорию товара и сохранить её в базу данных.

## Функциональные требования

### 1. Навигация (Sidebar)

- На всех страницах приложения (чеки, товары, детали чека) должно отображаться **боковое меню (sidebar)**
- В sidebar должно быть как минимум два пункта: «Чеки» и «Товары»
- Текущий активный раздел должен быть визуально выделен
- Sidebar должен быть всегда доступен (не скрывается), пока пользователь аутентифицирован

### 2. Страница раздела «Товары» (route `/commodities`)

- Отдельный маршрут (route), который можно сохранить в закладки браузера и перейти по нему в любой момент при активной аутентификации
- При переходе на `/commodities` отображается страница со списком всех товаров текущего пользователя

### 3. Таблица товаров

Таблица должна содержать следующие колонки:

| Колонка | Описание |
|---------|----------|
| Магазин | Название магазина, в котором была совершена покупка |
| Дата покупки | Дата и время покупки (по аналогии с существующей реализацией — кликабельная ссылка) |
| Название товара | Наименование товара из чека |
| Количество | Количество единиц товара |
| Цена за единицу | Цена за одну единицу товара |
| Стоимость | Общая стоимость = количество × цена за единицу |
| Категория (только для админов) | Выпадающий список категорий для выбора/изменения |

Особенности поведения:
- **Дата покупки**: при клике должен открываться детальный просмотр чека (страница `ReceiptDetails`) аналогично тому, как это работает на текущей странице списка чеков
- **Категория (админ)**: рядом с названием категории отображается кнопка/иконка редактирования, при клике появляется выпадающий список с доступными категориями. После выбора категория сразу сохраняется в БД (или с подтверждением). Только пользователи с ролью администратора видят эту колонку и могут редактировать

### 4. Пагинация

- Таблица товаров должна поддерживать пагинацию с теми же возможностями, что и текущая таблица чеков (выбор размера страницы: 5, 10, 20, 50, 100)
- **Выбранный размер страницы должен сохраняться при переключении между разделами** (чеки ↔ товары). Т.е. если пользователь на странице чеков выбрал 20 строк на странице, при переходе в товары должно остаться 20, и наоборот

### 5. API (бэкенд)

Необходимо реализовать следующие новые эндпоинты:

#### `GET /api/commodities`
- Возвращает список товаров с пагинацией (limit, offset)
- Поддерживает фильтрацию по `userId` (текущий пользователь)
- Каждый элемент включает: название магазина, дату покупки, название товара, количество, цену за единицу, стоимость, идентификатор чека (для ссылки на детали), идентификатор и название категории (если назначена)
- Возвращает заголовок `X-Total-Count` с общим количеством товаров

#### `PUT /api/commodities/{id}/category`
- Доступен только для пользователей с ролью администратора
- Принимает идентификатор категории
- Сохраняет/обновляет категорию для указанного товара

### 6. Модель категорий товаров

Необходимо создать предопределённый справочник категорий товаров (аналогично `MerchantCategory` для магазинов). Примерный набор категорий:

- Продукты питания
- Одежда и обувь
- Электроника
- Косметика и гигиена
- Аптека
- Товары для спорта
- Товары для детей
- Канцтовары и книги
- Зоотовары
- Товары для дома
- Строительство и ремонт
- Автотовары
- Цветы
- Прочее

Категория должна быть представлена отдельной сущностью (enum или таблица в БД) с полями: `int Id`, `string Name`.

### 7. Существующий функционал (не сломать)

- **Страница «Чеки»** должна продолжать работать как и раньше. При переключении на неё из sidebar текущее состояние (пагинация, выбранный мерчант, детали чека) может сбрасываться, но настройка размера страницы (pageSize) сохраняется глобально
- **Детали чека** при переходе из товаров должны работать так же, как и при переходе из списка чеков
- **Авторизация**: все эндпоинты должны проверять аутентификацию и права администратора где необходимо

## Предполагаемые варианты реализации (без глубоких технических деталей)

1. **Фронтенд**:
   - Добавить `react-router-dom` или использовать History API для роутинга
   - Создать компонент `Sidebar` с пунктами навигации
   - Вынести настройку `pageSize` в контекст/общее состояние (например, React Context)
   - Создать компоненты: `CommoditiesPage`, `CommodityTable` (или расширить существующие)
   - API-слой: новый модуль `api/commodities.ts`
   - Типы: добавить `CommodityItemDto` в `types/commodity.ts`

2. **Бэкенд**:
   - Создать новый модуль `Commodities` в `Api/Modules/` с эндпоинтами
   - Создать (или использовать уже существующий) репозиторий для товаров
   - Создать Application сервис/контракты для чтения товаров
   - Добавить справочник категорий (enum или таблица)
   - Обновить `ReceiptReadService` чтобы передавать CategoryId в DTO

## Критерии готовности

- [ ] Раздел «Товары» доступен по маршруту `/commodities` и сохраняется в закладки
- [ ] Таблица товаров отображает все колонки согласно требованиям
- [ ] Пагинация работает, размер страницы сохраняется между разделами
- [ ] Клик по дате открывает детали чека
- [ ] Администраторы видят колонку «Категория» с возможностью выбора и сохранения
- [ ] Обычные пользователи не видят колонку «Категория»
- [ ] Все существующие функции раздела «Чеки» продолжают работать
- [ ] API эндпоинты реализованы с проверкой аутентификации и прав
