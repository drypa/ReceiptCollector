# Задача: Отключить синхронизацию с MongoDB в Analytics

## Бизнес-задача

Разработчикам сервиса Analytics при отладке требуется ускорять запуск приложения и работать только с данными из PostgreSQL, не задействуя MongoDB. Текущий процесс требует подключения к двум БД, что замедляет запуск (около 10-15 сек) и усложняет локальную отладку.

Ценность для заказчика:
- Ускорение старта сервиса в режиме разработки с 15 сек до ~2-3 сек
- Простота отладки: фокус на данных PostgreSQL без лишних зависимостей
- Снижение нагрузки на MongoDB при тестировании функционала Analytics
- Возможность изолированного тестирования логической части (парсинг, агрегация)

---

## Техническое решение

### Вариант 1: Переменная окружения

Пример запуска:
bash
export ANALYTICS_MONGO_ENABLED=false
./up.dev.sh

Когда переменная установлена в false, сервис не пытается подключиться к MongoDB.

Достоинства:
- Не требует изменений конфигов приложений
- Универсально для любых фреймворков (.NET, Go, Node.js)
- Проще всего внедрить: одна строка в .env или командной строке

### Вариант 2: Настройка в appsettings.Development.json (для .NET)

Добавить секцию в конфигурации:
json
{
  "DisableMongoSync": true
}

Или через флаг в ConnectionStrings для принудительного отключения.

---

## Реализация (.NET)

### 1. Проверка на этапе инициализации подключений к БД

При создании сервисов нужно проверять флаги: если MongoDB не требуется, то этот сервис не регистрируется. Это сокращает время инициализации запуска.

### 2. Добавление настроек в appsettings.Development.json

В конфигурации разработчика добавить возможность указать отключение синхронизации с MongoDB отдельно о остальных зависимостей.

---

## План реализации

1. Добавить проверку в appsettings.Development.json (или .env) для отключения MongoDB
2. Изменить логику инициализации сервисов, чтобы они не зависели от подключения к MongoDB
3. Обновить документацию по запуску сервиса Analytics
4. Добавить флаг EnableMongoSync: false в конфиг разработки

---

## Оценка времени / сложности

- Добавление проверки в конфиг: 15 мин
- Изменение инициализации сервисов: 45 мин
- Обновление документации: 15 мин

Итого: ~1 час работы (подрядчика)

---

## Примечания к тестированию

- Проверить запуск без подключения к MongoDB
- Убедиться, что функционал Analytics работает корректно с данными PostgreSQL
- Проверить graceful shutdown (отсутствие зависаний процессов)
