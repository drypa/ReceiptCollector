# Настраиваемая директория выдачи сертификатов в generate-ssl-cert.sh

## Приоритет
medium

## Проблема
Скрипт `generate-ssl-cert.sh` всегда генерирует ключи и сертификаты в каталог `./ssl` рядом со скриптом. При деплое в Docker-окружении сертификаты должны попадать в монтируемый каталог (например, `/usr/share/receipts/ssl/certs/`, заданный через `SSL_CERTS_PATH` в `.env`). Сейчас после генерации их приходится вручную копировать в нужное место.

## Цель
Если в `.env` задана переменная `SSL_CERTS_PATH` — генерировать ключи и сертификаты по этому пути. Если переменная не задана — сохранить текущее поведение (дефолтный каталог `./ssl`).

## Пользователи
Разработчик / администратор при деплое в Docker-окружении.

## Сценарий использования
1. В `.env` задана `SSL_CERTS_PATH=/usr/share/receipts/ssl/certs/`
2. Запустить `./generate-ssl-cert.sh`
3. Скрипт читает `SSL_CERTS_PATH` из `.env`
4. Если целевого каталога нет — создаёт его рекурсивно (`mkdir -p`)
5. Все файлы (`fullchain.pem`, `private.key`, `root.crt`, `root.key`) создаются в этом каталоге
6. Если каталог уже содержит CA (`root.crt`/`root.key`) — поведение не меняется: CA переиспользуется (как и раньше)

## Критерии приёмки
- [ ] При заданной `SSL_CERTS_PATH` (с завершающим слэшем и без него) файлы `fullchain.pem`, `private.key`, `root.crt`, `root.key` появляются в этом каталоге
- [ ] Каталог создаётся рекурсивно, если его нет
- [ ] При отсутствии `SSL_CERTS_PATH` в `.env` сертификаты по-прежнему генерируются в `./ssl` (дефолтное поведение без изменений)
- [ ] Существующий CA в целевом каталоге переиспользуется — поведение генерации не меняется
- [ ] Скрипт завершается без ошибок во всех трёх вариантах

## Edge cases
- `SSL_CERTS_PATH` задана с завершающим слэшем и без него — оба варианта должны обрабатываться корректно (нормализация пути)
- `SSL_CERTS_PATH` указывает на каталог с уже существующими сертификатами — поведение не меняется (CA переиспользуется)
- `SSL_CERTS_PATH` не задана — дефолт `./ssl`

## Зависимости
- Переменная `SSL_CERTS_PATH` уже используется сервисами (см. таблицу конфигурации в AGENTS.md)
- OpenSSL установлен в среде запуска
