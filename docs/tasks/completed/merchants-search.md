# Поиск магазинов на странице `/merchants`

## Приоритет
medium

## Проблема
На странице магазинов `/merchants` (Analytics, раздел для администраторов) нет поиска. При большом количестве магазинов администратору сложно быстро найти нужный магазин по названию или ИНН — приходится просматривать страницы списка вручную.

## Цель
Добавить на страницу `/merchants` поиск по названию и ИНН, чтобы администратор мог быстро находить нужные магазины без ручного перебора страниц.

## Пользователи
- Администратор системы (страница `/merchants` остаётся доступной только администраторам).

## Сценарий использования
1. Администратор открывает страницу `/merchants`.
2. Вводит в поле поиска часть названия магазина или часть ИНН.
3. Список магазинов фильтруется по введённому фрагменту (совпадение по названию или по ИНН), отображается первая страница результатов.
4. Администратор переходит по страницам отфильтрованного списка при необходимости.
5. Администратор очищает поле поиска — отображается полный список магазинов (с корректной пагинацией).

## Критерии приёмки
- [ ] На странице `/merchants` доступно поле поиска (одно поле), работающее по образцу поиска на странице «Предкатегоризация»: ввод с задержкой (debounce), при изменении запроса происходит сброс на первую страницу; плейсхолдер в духе «Название или ИНН».
- [ ] Поиск выполняется по **названию** магазина: частичное совпадение, без учёта регистра.
- [ ] Поиск выполняется по **ИНН**: частичное совпадение. Если введённый фрагмент совпадает и с названием, и с ИНН, в результатах отображаются все совпадения.
- [ ] Фильтрация выполняется на бэкенде (через параметр поиска API), чтобы серверная пагинация не ломалась: общее количество (`total`) и навигация по страницам считаются по отфильтрованному набору.
- [ ] Очистка поля поиска возвращает полный список магазинов.
- [ ] Пагинация корректно работает вместе с поиском и после его очистки (включая сброс на первую страницу при новом запросе).
- [ ] Подсветка совпадений в результатах не требуется.
- [ ] Остальной функционал страницы (таблица, выбор размера страницы, обновление, действия с магазинами) и ограничения доступа (только администратор) остаются без изменений.

## Edge cases
- Магазины без ИНН: поиск по названию для них должен работать; отсутствие ИНН не должно приводить к ошибкам при фильтрации по ИНН.
- Пустой результат поиска: отображается корректное состояние «ничего не найдено» (в рамках существующего поведения таблицы/страницы), пагинация соответствует пустому/нулевому набору.
- Фрагмент, совпадающий одновременно с названием одного магазина и ИНН другого: в выдаче присутствуют оба.

## Зависимости
- Существующая страница и API списка магазинов в Analytics (`/merchants`, `/api/merchants`).
- Референс поведения/UI поиска — страница «Предкатегоризация».
