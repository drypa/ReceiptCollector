# Задача: Заменить gorilla/mux на стандартный роутер Go

- **Статус:** техническое решение готово ([ADR-014](../adr/014-replace-gorilla-mux.md)), ожидает реализации
- **Автор:** менеджер проекта
- **Дата создания:** 2026-08-22
- **Приоритет:** средний
- **Исполнитель:** @software-architect (техническое решение)

## 1. Бизнес-задача

В backend-сервисе (сбор чеков с nalog.ru) для обработки HTTP-запросов используется
сторонняя библиотека `github.com/gorilla/mux`. Требуется заменить её на стандартный
роутер языка Go (`net/http`).

### Предыстория

Библиотека `gorilla/mux` долгое время не имела официального сопровождения, а начиная
с Go 1.22 стандартная библиотека покрывает её ключевую функциональность (переменные
в пути и привязка HTTP-методов). Держать зависимость ради того, что уже есть «из
коробки», — лишний риск и обслуживание.

## 2. Ценность для заказчика

- **Меньше внешних зависимостей** — на одну стороннюю библиотеку меньше в цепочке
  поставки: ниже риск от несовместимых обновлений и уязвимостей в транзитивных
  пакетах.
- **Снижение стоимости сопровождения** — код на стандартной библиотеке понятнее
  новым разработчикам, проще проходить ревью и security-аудиты (CodeQL).
- **Долгосрочная устойчивость** — стандартный роутер развивается вместе с языком,
  нет риска «брошенного» пакета.
- **Без изменений для пользователя** — все клиенты (фронтенд, Telegram-бот)
  продолжают работать по тем же адресам и методам; поведение API не меняется.

## 3. Объём работ (scope)

Затронут только backend-сервис (`backend/`). Сервис `bot/` данную библиотеку
не использует — изменения его не касаются.

Текущее использование `gorilla/mux` в backend:

| Место | Что используется |
|---|---|
| `backend/main.go` | регистрация всех маршрутов, два набора роутов: `/api/*` (под BasicAuth) и internal-роуты для бота |
| `backend/receipts/controller.go` | извлечение параметров из пути (`{id}`) |
| `backend/markets/controller.go` | извлечение параметров из пути (`{id}`) |
| `backend/users/controller.go` | извлечение параметров из пути |

Маршруты, которые должны продолжить работать без изменений:

| Маршрут | Методы |
|---|---|
| `/api/market/{id:[a-zA-Z0-9]+}` | PUT, GET, DELETE |
| `/api/receipt` | GET |
| `/api/receipt/{id:[a-zA-Z0-9]+}` | GET, DELETE |
| `/api/receipt/from-bar-code` | POST |
| `/api/receipt/batch` | POST |
| `/api/device` | POST |
| `/api/waste` | GET |
| логин-маршрут (`/api/login`) | POST |
| маршрут регистрации | POST |
| регистрация по Telegram ID | POST |
| добавление чека пользователю Telegram | POST |
| `/internal/...` | внутренний API бота |

## 4. Критерии приёмки

1. Прямая зависимость `github.com/gorilla/mux` полностью удалена из `go.mod` /
   `go.sum` backend-сервиса; в коде не осталось импортов библиотеки.
2. Все перечисленные маршруты отвечают так же, как раньше:
   - те же пути (включая ограничения на символы в `{id}`);
   - те же HTTP-методы;
   - запрос с неподдерживаемым методом возвращает ошибку, как раньше;
   - BasicAuth по-прежнему применяется ко всем `/api/*` и не применяется к
     internal-роутам.
3. Поведение API для клиентов не изменилось (проверить вручную или тестами:
   фронтенд и Telegram-бот работают без правок).
4. `cd backend && go build ./...` и `cd backend && go test ./...` проходят успешно.
5. Сборка Docker-образа backend проходит успешно.

## 5. Вне объёма (out of scope)

- Любые изменения бизнес-логики обработчиков маршрутов.
- Изменения контрактов API (пути, форматы запросов/ответов, коды ответов).
- Рефакторинг gRPC-части, воркеров, Telegram-бота.
- Замена других сторонних зависимостей.

## 6. Открытые вопросы / риски

1. В текущих маршрутах используются ограничения на переменные пути
   (`{id:[a-zA-Z0-9]+}`). Стандартный роутер поддерживает подстановку `{id}`,
   но не регулярные выражения напрямую. Архитектору нужно предложить способ
   сохранить текущее поведение (например, валидация идентификатора в обработчике
   или middleware) — выбор за архитектором.
2. Необходимо проверить, как сейчас ведут себя несуществующие пути и методы
   (какой код ответа возвращается), чтобы сохранить совместимость.

## 7. Техническое решение

Оформлено как [ADR-014: Замена gorilla/mux на стандартный роутер net/http](../adr/014-replace-gorilla-mux.md).

Ключевые пункты решения:
- роутинг на `http.ServeMux` (Go 1.22+): `"METHOD /path/{id}"`, литералы выигрывают у wildcard — конфликтов `/api/receipt/from-bar-code` vs `/api/receipt/{id}` нет;
- ограничение `{id:[a-zA-Z0-9]+}` сохраняется валидацией в общем хелпере `backend/route.PathID`, невалидный id → 404 (как раньше);
- `mux.Vars` заменяется на `request.PathValue` в телах локальных хелперов трёх контроллеров;
- BasicAuth: два дерева mux — authed `/api/*` и открытые `login` / `register` / `/internal/*`;
- **найден квирк main.go**: обёртка BasicAuth регистрировалась в `DefaultServeMux`, а сервер работает с «сырым» router — BasicAuth фактически не действовал. Включение реального BasicAuth меняет наблюдаемое поведение — вопрос вынесен владельцу продукта (см. ADR, «Открытые вопросы»);
- совместимость кодов ответов (404/405) фиксируется таблицей httptest-тестов.
