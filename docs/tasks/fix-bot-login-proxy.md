# Исправление команды /login: обход Squid-прокси для внутренних сервисов

## Приоритет
blocker

## Проблема
Команда `/login` в Telegram-боте не работает: пользователь получает ошибку Squid-прокси вместо ссылки на авторизацию. HTTP-клиент бота (`bot/analytics/client.go`) использует `http.DefaultTransport`, который направляет **все** HTTP-запросы через `HTTP_PROXY` (Squid). Squid не может достучаться до внутреннего сервиса `analytics` в Docker-сети, поэтому запрос `/api/users/auth/link` завершается ошибкой.

В логах `receipt-bot` и `receipt-collector` ошибок нет — проблема происходит на уровне HTTP-клиента бота, до попадания в логи сервисов. Прокси нужен только для доступа к Telegram API (внешний трафик).

## Цель
Команда `/login` возвращает пользователю ссылку на авторизацию в Analytics. Все внутренние сервисы бот должен вызывать напрямую, минуя прокси; через Squid должен идти только внешний трафик (Telegram API).

## Пользователи
Все пользователи Telegram-бота. Это единственный способ получить доступ к Analytics — других входных точек нет и быть не должно.

## Сценарий использования
1. Пользователь отправляет `/login` в Telegram.
2. Бот вызывает `GET /api/users/auth/link?telegramId={id}` у внутреннего сервиса `analytics` напрямую, без прокси.
3. Analytics возвращает ссылку.
4. Бот отправляет ссылку пользователю.

## Критерии приёмки
- [ ] `/login` в Telegram возвращает ссылку на авторизацию в Analytics (happy path)
- [ ] Все внутренние сервисы Docker-сети (analytics, collector/backend и др.) доступны боту напрямую, минуя прокси
- [ ] Трафик к Telegram API по-прежнему идёт через Squid (прокси не отключается полностью)
- [ ] Ошибки Squid-прокси в ответах команды `/login` исчезают

## Edge cases
- Прокси не задан (`TG_PROXY_URL` пустой) — поведение бота не должно меняться
- Стандартные `HTTP_PROXY`/`HTTPS_PROXY`/`NO_PROXY` не должны попадать в контейнер бота (иначе неявный прокси вернётся через `http.DefaultTransport`)
- Решение должно работать в проде через `docker-compose.yml` (в контейнере бота)
- Другие команды бота, которые ходят к внутренним сервисам, не должны ломаться

## Зависимости
- `bot/analytics/client.go` — HTTP-клиент, использующий `http.DefaultTransport`
- `docker-compose.yml` — переменная прокси для контейнера бота (строка ~77)
- `bot/bot.go` — создание Telegram API-клиента с прокси (не затрагивать)
