# Постановка задачи при декомпозиции фичи

## Общие принципы

1. **Ясность и понятность**: Задача должна быть описана на русском языке, без использования эмодзи и прочих смайликов.
2. **Уровень детализации**: Описание должно быть достаточно подробным, чтобы его можно было отдать младшему разработчику на реализацию.
3. **Структура задачи**:
   - Приоритет
   - Цель
   - Описание проблемы
   - План решения (пошаговое описание)
   - Тестирование (команды и ожидаемые результаты)
   - Критерии успеха

## Пример структуры задачи

### Заголовок
- **Приоритет**: Уровень важности задачи (например, CRITICAL, HIGH).
- **Цель**: Краткое описание цели задачи.

### Описание проблемы
- **Локация**: Путь к файлу и строки, где находится проблема.
- **Текущий код**: Пример кода с проблемой.
- **Проблема**: Описание проблемы и ее влияния на систему.

### План решения
- **Шаг 1**: Первое действие для исправления проблемы.
- **Шаг 2**: Второе действие для исправления проблемы.
- **...**: Дополнительные шаги при необходимости.

### Тестирование
- **Команды**: Команды для проверки исправления.
- **Ожидаемые результаты**: Описание ожидаемых результатов после выполнения команд.

### Критерии успеха
- Список критериев, которые должны быть выполнены для успешного завершения задачи.
