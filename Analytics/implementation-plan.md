Версия: 1.0  
Дата: 2025-10-08  
Подготовлено для: AI-агента (вспомогательная автоматизация разработки)

---

## 🎯 Цель
Определить пошаговый план реализации проекта, чтобы AI-агент мог:
- помогать с генерацией кода и конфигураций;
- контролировать прогресс задач;
- поддерживать архитектурную целостность;
- автоматически создавать документацию, тесты и CI/CD конфиги.

## 🧩 Этапы реализации

**Задачи:**

- Postgres

**Выходные артефакты:**
- `docker-compose.yml`
- `README.md`

### Этап 2. Backend: базовая архитектура (.NET API)
**Цель:** реализовать каркас API и доменные сущности.

**Задачи:**
1. Создать ASP.NET Web API проект в `/backend`.
2. Настроить подключение к PostgreSQL через EF Core.
3. Определить модели:
- `User`
- `Receipt`
- `Commodity`
- `Category`
- `CategorizationRule`
4. Настроить миграции EF Core + seed данных для категорий.
5. Добавить Swagger / OpenAPI.
6. Реализовать первые эндпоинты получения списка чеков и деталей конкретного чека:
- `GET /api/receipts`
- `GET /api/receipts/{id}`
7. Подготовить unit-тесты для моделей и мапперов.

### Этап 4. Categorization Service
**Цель:** автоматическая и ручная категоризация.

**Задачи:**
1. Реализовать `CategorizationService`:
- Простое keyword-matching.
- Конфигурация правил через БД (`CategorizationRule`).
2. Создать API для ручной коррекции.
3. Настроить обновление правил после автоматической и ручной категоризации.
4. Подготовить тесты с разными сценариями (auto/manual).

### Этап 5. Frontend (React)
**Цель:** реализовать пользовательский интерфейс и админ-панель с поддержкой автоматического входа через Telegram.

**Задачи:**
1. Создать React-приложение в `/frontend`.
2. Реализовать страницы:
    - Dashboard пользователя (чеки, аналитика).
    - Admin UI (ручная категоризация, категории, правила).
3. Добавить поддержку **автоматического входа через одноразовую ссылку**:
    - При переходе по ссылке из Telegram (`https://app.example.com/login?token=<one_time_token>`) фронтенд вызывает `/api/auth/telegram-link-login`.
    - API возвращает `JWT` и `refresh_token`.
    - Токен сохраняется в localStorage / cookie.
4. Реализовать хук `useAuth()`:
    - Проверяет наличие токена и подставляет Authorization в запросы.
    - Перенаправляет неавторизованных пользователей на страницу “Авторизация через Telegram”.
5. Настроить взаимодействие с API (axios, react-query).
6. Добавить тесты:
    - Проверка авто-входа по токену.
    - Проверка поведения при истечении токена.
7. Подключить OpenAPI client (автогенерация типов).

### Этап 6. Аутентификация через Telegram (одноразовая ссылка)
**Цель:** реализовать безопасный процесс автоматического входа по одноразовой ссылке, полученной из Telegram.

**Задачи:**
1. Реализовать `AuthGateway` (ASP.NET):
   - Telegram-бот по запросу пользователя генерирует одноразовый токен (`one_time_token`), связанный с `telegram_id`.
   - Токен хранится в Redis с TTL (например, 60 секунд).
2. Реализовать API эндпоинт:
   - `GET /api/auth/telegram-link-login?token=<one_time_token>`
   - Проверяет токен в Redis.
   - Если валидный — выдает `JWT` + `refresh_token` и удаляет токен.
   - Если недействительный — возвращает 401.
3. Добавить поддержку refresh-токенов (через Postgres).
4. Добавить middleware авторизации JWT.
5. Telegram-бот должен уметь:
   - При команде `/login` отправлять пользователю одноразовую ссылку.
   - Пример: `https://app.example.com/login?token=<generated_token>`
6. Добавить логику безопасного завершения сессии:
   - `POST /api/auth/logout` → инвалидация refresh-токена.
7. Добавить юнит- и интеграционные тесты:
   - Проверка выдачи токена ботом.
   - Проверка автоматического входа по ссылке.
   - Проверка истечения токена.
